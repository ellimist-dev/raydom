# Images

## Loading

```c
rd_image logo = rd_image_load_file(ctx, "logo.png");  // or rd_image_load(ctx, bytes, size) for #embed data
if (logo.id == 0) {
  // missing or unreadable file: fall back to generated pixels
}
```

raydom decodes PNG, JPEG, BMP, GIF (the first frame), TGA and PSD with a vendored copy of stb_image, so the formats
don't depend on how raylib was built. SVG is covered [below](#svg). Decoding happens at load; the texture is created on the first draw. Loading
and layout therefore work before `InitWindow` and in headless tests.

For a single binary, embed the file and load it from memory:

```c
static const unsigned char logo_png[] = {
#embed "logo.png"
};
rd_image logo = rd_image_load(ctx, logo_png, sizeof logo_png);
```

Pixels generated by the program work the same way:

```c
int            w = 64, h = 32;
unsigned char* rgba = calloc((size_t)w * (size_t)h, 4);
for (int i = 0; i < w * h; i++) rgba[i * 4 + 0] = rgba[i * 4 + 3] = 255;  // opaque red
rd_image swatch = rd_image_from_pixels(ctx, rgba, w, h);                 // copied; rgba can be freed
free(rgba);
```

## SVG

`rd_image_load` and `rd_image_load_file` recognize SVG documents by their content and parse them with a vendored
copy of nanosvg. An SVG's natural size comes from its `width` and `height`, or its `viewBox`. It is rasterized when
drawn, at the size it's drawn at times the display scale, so it stays sharp at any size; when drawn larger later,
it's rasterized again. The raster's scale goes up in steps of 1.25, so an SVG growing a little each frame, as in a
pane being resized, is rasterized every few steps rather than every frame. Smaller uses sample the larger raster.

```c
rd_image icon = rd_image_load(ctx, icon_svg, sizeof icon_svg - 1);
rd_node  n    = rd_node_create(ctx);
rd_node_set_image(ctx, n, icon);
rd_node_set_style(ctx, n, &(rd_style){.height = rd_px(20), .color = rd_hex(0x5b8cff)});  // 20px, blue
```

An SVG that uses `currentColor` is drawn tinted by the node's `color`, which is inherited, so icons match the text
around them. The tint applies to the whole icon: in an SVG that mixes `currentColor` with other colors, the other
colors are tinted too. Monochrome icon sets (Lucide, Heroicons, Feather) work as intended.

nanosvg covers paths, basic shapes, strokes, fills, opacity and gradients. It doesn't support text, filters, masks,
clip paths, patterns or embedded images. See [Limits](../reference/limits.md).

## Image nodes

```c
rd_node banner = rd_node_create(ctx);
rd_node_set_image(ctx, banner, swatch);
rd_node_set_style(ctx, banner, &(rd_style){.width = rd_px(200)});  // height follows: 100
rd_node_append(ctx, root, banner);

rd_node avatar = rd_node_create(ctx);
rd_node_set_image(ctx, avatar, swatch);
rd_node_set_style(ctx, avatar, &(rd_style){.width          = rd_px(48),
                                           .height         = rd_px(48),
                                           .object_fit     = RD_OBJECT_FIT_COVER,
                                           .border_radius  = rd_corners_all(rd_px(24))});  // a circle
rd_node_append(ctx, root, avatar);
```

`rd_node_set_image` makes the node an image leaf. It is sized like an HTML `<img>`:

| Style sets       | Size                                           |
| ---------------- | ---------------------------------------------- |
| Nothing          | The image's size in pixels, as logical pixels  |
| `width` only     | That width; height from the aspect ratio       |
| `height` only    | That height; width from the aspect ratio       |
| Both             | Both; `object_fit` decides how the image fills |

A stretched item in a column (the default `align_items`) has a definite width, so it fills the column and takes its
height from the ratio.

`object_fit` places the image in the content box. The image is centered, and cropped where it overflows:

| `object_fit` | Result                                              |
| ------------ | --------------------------------------------------- |
| `FILL`       | Stretched to the box (the default)                  |
| `CONTAIN`    | As large as fits, aspect ratio kept, letterboxed    |
| `COVER`      | Covers the box, aspect ratio kept, edges cropped    |
| `NONE`       | Natural size                                        |
| `SCALE_DOWN` | `NONE` or `CONTAIN`, whichever is smaller           |

`border_radius` clips the image, less the node's border and padding, so a square node with `COVER` and a radius of
half its size is a round avatar. `opacity` fades it. Background and border draw behind it as on any node.

C++: `ctx.create_image(img, style)` creates an image node with the image [role](roles.md).

## Changing and freeing

```c
unsigned char frame[16 * 16 * 4] = {0};
rd_image_update(ctx, swatch, frame, 16, 16);  // a new size: nodes showing it relayout
rd_image_unload(ctx, logo);                   // safe on a null image
```

`rd_image_update` replaces the pixels, for video frames, emulator screens or anything drawn on the CPU. The texture is
updated in place when the size is unchanged. `rd_image_unload` frees the pixels and texture; nodes showing the image
collapse and draw nothing. Image handles aren't reused, so a stale handle stays null. Everything is freed with the
context.

Textures get mipmaps and trilinear filtering, so images stay smooth when drawn smaller than their size.

raydom

Introduction

raydom is a retained-mode UI tree for raylib. An application builds a tree of nodes, assigns CSS-like styles, and attaches event listeners. raydom computes layout with flexbox and grid, shapes and wraps text, routes pointer and keyboard input, and draws the result with raylib. The core is C23; a header-only C++20 layer wraps it. Applications link it statically and ship as one binary.

This book documents the version shown in the version menu. Each release tag has its own copy of the book, so the pages you read match the headers you compile against.

Model

  • Context. rd_ctx owns every node, style, class, font and listener. Destroying it frees all of them.
  • Nodes. rd_node is a small value handle. A handle to a destroyed node is stale; every call on it is a no-op.
  • Styles. A node’s computed style merges defaults, inherited properties, classes, state variants, and the inline style, in that order.
  • Frame loop. Each frame, rd_update feeds raylib’s input and lays the tree out at the window size, and rd_draw draws it.

How to read this book

Getting started covers installation and a first window. The guide has one chapter per subsystem. The reference lists every style property with its type, default and inheritance.

Every code sample in this book is a fragment of a program under docs/examples/ in the repository. Those programs are compiled by the test suite, and the ones that don’t open a window run as tests, so the samples compile and behave as described for this version.

Quickstart

raydom has no built-in font. Load a TrueType or OpenType file before creating text; the first font loaded becomes the default for every node.

C

#include <raydom/raydom.h>
#include <raylib.h>

int main(void) {
  SetConfigFlags(FLAG_WINDOW_HIGHDPI | FLAG_WINDOW_RESIZABLE);
  InitWindow(800, 600, "hello");
  rd_ctx* ctx = rd_ctx_create();
  rd_font_load_file(ctx, FONT_PATH);  // any .ttf or .otf file

  rd_node card = rd_node_create_text(ctx, "Hello from raydom", RD_TEXT_NUL);
  rd_node_set_style(ctx, card,
                    &(rd_style){
                        .padding       = rd_edges_all(rd_px(16)),
                        .border_radius = rd_corners_all(rd_px(8)),
                        .background    = rd_hex(0x1a1f2b),
                        .color         = rd_hex(0xe4e7ee),
                    });
  rd_node_append(ctx, rd_ctx_root(ctx), card);

  while (!WindowShouldClose()) {
    rd_update(ctx);  // input, then layout at the window size
    BeginDrawing();
    ClearBackground(BLACK);
    rd_draw(ctx);
    EndDrawing();
  }
  rd_ctx_destroy(ctx);  // before CloseWindow, so GPU resources are released
  CloseWindow();
}

C++

#include <raydom/raydom.hh>
#include <raylib.h>

#include <string>

using namespace rd::literals;

int main() {
  SetConfigFlags(FLAG_WINDOW_HIGHDPI | FLAG_WINDOW_RESIZABLE);
  InitWindow(800, 600, "hello");
  {
    rd::Context ctx;
    ctx.load_font_file(FONT_PATH);  // any .ttf or .otf file

    rd::Class button_style = ctx.create_class(rd::Style()
                                                  .padding(8_px, 16_px)
                                                  .border_radius(8_px)
                                                  .background(rd::hex(0x5b8cff))
                                                  .color(rd::hex(0xffffff)));
    button_style.on(RD_STATE_HOVER, rd::Style().background(rd::hex(0x7aa2ff)));

    int      clicks = 0;
    rd::Node label  = ctx.create_text("Clicked 0 times", rd::Style().color(rd::hex(0xe4e7ee)));
    rd::Node button = ctx.create_button("Click me").add_class(button_style);  // Tab focuses it; Enter and Space click it
    button.on_click([&] { label.text("Clicked " + std::to_string(++clicks) + " times"); });

    ctx.root()
        .style(rd::Style().padding(24_px).row_gap(12_px).align_items(RD_ALIGN_START))
        .append(button)
        .append(label);

    while (!WindowShouldClose()) {
      ctx.update();
      BeginDrawing();
      ClearBackground(BLACK);
      ctx.draw();
      EndDrawing();
    }
  }  // the context is destroyed here, before CloseWindow
  CloseWindow();
}

The C++ context is an RAII owner. It is scoped inside a block so it is destroyed before CloseWindow; raydom owns GPU textures and a shader that must be released while the window still exists.

The frame loop

while (!WindowShouldClose()) {
  rd_update(ctx);
  BeginDrawing();
  ClearBackground(BLACK);
  rd_draw(ctx);
  EndDrawing();
}

rd_update does these things, in order:

  1. Sets the context clock from GetTime() (rd_ctx_set_time), which fires due timers.
  2. Feeds raylib’s keyboard and text input (rd_ctx_key, rd_ctx_text).
  3. Feeds the mouse position, buttons and wheel (rd_ctx_pointer). Listeners run here.
  4. Lays the tree out at the screen size (rd_ctx_layout): advances animations, computes styles, lays out, and places anchored nodes.
  5. Applies the mouse cursor, and, with rd_set_event_waiting, raylib’s event waiting.

rd_draw builds a display list from the laid-out tree and executes it with raylib. It must be called between BeginDrawing and EndDrawing. Anything drawn with raylib after rd_draw appears on top of the UI.

Mutating the tree

Tree and style changes are allowed at any time: in listeners, between frames, or from application logic. They are recorded as dirty flags; nothing is recomputed until the next layout. Several changes in one frame cost one layout.

Geometry queries such as rd_node_rect return the result of the most recent layout. After changing the tree outside the frame loop, call rd_ctx_layout before reading geometry.

Without raylib input

rd_update is a convenience. Applications with their own input handling, and tests, call the lower-level functions directly:

rd_ctx_set_time(ctx, seconds);
rd_ctx_pointer(ctx, x, y, RD_BUTTON_PRIMARY, 0, 0);  // position, held buttons, wheel
rd_ctx_key(ctx, RD_KEY_TAB, true, false, 0);          // key, down, repeat, modifiers
rd_ctx_text(ctx, 'a');                                // one codepoint
rd_ctx_layout(ctx, width, height);

Nothing except rd_update, rd_draw, and paint callbacks touches raylib, so a context can be built, laid out and driven with input without a window. The headless examples behind the guide chapters run this way.

Timers

Timers run on the context’s clock. rd_update sets the clock from raylib each frame, before input, and every due timer fires then, on the main thread, so callbacks may change the tree like any listener.

static void hide_toast(rd_ctx* ctx, void* data) {
  toast* t = data;
  rd_node_merge_style(ctx, t->node, &(rd_style){.display = RD_DISPLAY_NONE});
}

static void show_toast(rd_ctx* ctx, toast* t) {
  rd_node_merge_style(ctx, t->node, &(rd_style){.display = RD_DISPLAY_FLEX});
  rd_ctx_clear_timer(ctx, t->hide);  // showing again restarts the countdown
  t->hide = rd_ctx_set_timer(ctx, 2.0, 0, hide_toast, t, NULL);
}

int      seconds = 0;
rd_timer clock   = rd_ctx_set_timer(ctx, 1.0, RD_TIMER_REPEAT, tick, &seconds, NULL);
// ... later
rd_ctx_clear_timer(ctx, clock);

A one-shot timer is destroyed after it fires; clearing it afterwards is a harmless no-op, so “clear, then set” is the restart idiom. A repeating timer that falls behind (the window was minimized, say) fires once and skips the rest. A timer set from a timer callback doesn’t fire until the next clock update, so callbacks can’t loop forever within one frame. destroy(data) runs when a timer is cleared, a one-shot has fired, or the context is destroyed.

C++: ctx.set_timeout(2.0, [&] { ... }) and ctx.set_interval(1.0, [&] { ... }) return an rd_timer for ctx.clear_timer.

Event waiting

raylib’s EnableEventWaiting makes idle frames block until input arrives, which saves power but would also stall timers. Let raydom manage it instead:

rd_set_event_waiting(ctx, true);  // instead of EnableEventWaiting()

rd_update then turns raylib’s event waiting off while any timer is pending or anything animates, and back on when neither is true, so a tooltip delay or toast fires on time and an idle UI still costs nothing. A repeating timer keeps frames running for as long as it exists.

Lifetime

Destroy the context before CloseWindow. rd_ctx_destroy frees every node and runs every destroy callback registered for userdata, listeners, measure and paint functions.

Nodes and the tree

A context starts with one node, the root, which is sized to the layout viewport. Every other node is created detached and becomes visible when it is attached under the root.

rd_ctx* ctx  = rd_ctx_create();
rd_node root = rd_ctx_root(ctx);

rd_node list = rd_node_create(ctx);
rd_node a = rd_node_create(ctx), b = rd_node_create(ctx), c = rd_node_create(ctx);
rd_node_append(ctx, root, list);
rd_node_append(ctx, list, a);
rd_node_append(ctx, list, c);
rd_node_insert_before(ctx, list, b, c);  // list: a, b, c

Handles

rd_node is {index, gen}. The context stores nodes in a slot array; index names a slot and gen counts how many times that slot has been reused. Destroying a node bumps its slot’s generation, so old handles stop matching.

Consequences:

  • Handles are plain values. Copy them, store them in structs, compare them with rd_node_eq.
  • A stale handle is safe. Every function checks it and returns false, a null node, or does nothing.
  • rd_node_is_null tests for the zero handle, which functions return on failure. It doesn’t test liveness; use rd_node_alive for that.

Walking

for (rd_node n = rd_node_first_child(ctx, list); !rd_node_is_null(n); n = rd_node_next_sibling(ctx, n)) {
  // visit n
}

C++ offers for (rd::Node child : node.children()). Neither form is stable if the loop body adds or removes siblings of the node being visited; collect the nodes first in that case.

Moving and detaching

rd_node_append(ctx, root, b);  // moving: b leaves list and becomes root's last child
rd_node_detach(ctx, c);        // c stays alive, owned by the context, outside the tree
rd_node_append(ctx, list, c);  // and can be attached again later

rd_node_append and rd_node_insert_before move a node that already has a parent. They fail, returning false, when the move would create a cycle, or when either handle is stale. A detached node keeps its subtree, styles and listeners. It isn’t laid out, drawn or hit-tested.

Userdata

Each node carries one void* and an optional destroy callback that runs when the node is destroyed or the userdata is replaced.

typedef struct item {
  int id;
} item;

static void free_item(void* data) { free(data); }

item* data = malloc(sizeof *data);
data->id   = 7;
rd_node_set_userdata(ctx, a, data, free_item);
item* back = rd_node_userdata(ctx, a);

C++: node.emplace_userdata<T>(args...) allocates a T owned by the node, and node.userdata<T>() returns it.

Extension storage

Libraries built on raydom can keep per-context data without a global map:

static const char key;  // any address the library owns
rd_ctx_set_extension(ctx, &key, data, free_data);  // destroyed with the context
my_state* s = rd_ctx_extension(ctx, &key);

The extras controls keep their classes and state this way, which leaves every node’s userdata to the application.

Destroying

rd_node_destroy(ctx, list);         // destroys list, a and c; a's userdata is freed
bool alive = rd_node_alive(ctx, a);  // false: the handle is stale, and every call on it is a no-op

rd_node_destroy destroys the subtree, depth first, and runs its destroy callbacks. The root can’t be destroyed. Destroying a node from inside one of its own listeners is allowed; see Events.

Styles and classes

rd_style is a struct with one field per property. Every field type reserves zero for “unset”, so a compound literal names only the properties it sets. The property reference lists them all.

Inline styles

rd_node_set_style(ctx, node,
                  &(rd_style){
                      .width         = rd_px(240),
                      .padding       = rd_edges_vh(rd_px(8), rd_px(12)),  // vertical, horizontal
                      .border_width  = rd_edges_all(rd_px(1)),
                      .border_color  = rd_hex(0x272d3a),
                      .border_radius = rd_corners_all(rd_px(6)),
                      .background    = rd_hex(0x1a1f2b),
                  });
rd_node_merge_style(ctx, node, &(rd_style){.padding.left = rd_px(20)});  // only the left side changes

rd_node_set_style replaces the inline style. rd_node_merge_style copies the set fields over it and leaves the rest. Passing NULL to rd_node_set_style clears it.

Value constructors: rd_px, rd_pct, rd_num, rd_fr, rd_auto(), rd_min_content(), rd_max_content(). Colors: rd_hex(0xRRGGBB), rd_rgb, rd_rgba. Box sides: rd_edges_all, rd_edges_vh, or designated .padding.left. See Values and units.

Classes

A class is a reusable style with optional variants per state. Classes live until the context is destroyed; rd_class_set replaces a class’s base style and restyles every node that uses it.

rd_class button_style = rd_class_create(ctx, &(rd_style){.padding    = rd_edges_vh(rd_px(6), rd_px(14)),
                                                        .background = rd_hex(0x1d2230)});
rd_class primary      = rd_class_create(ctx, &(rd_style){.background = rd_hex(0x5b8cff)});
rd_class_set_state(ctx, button_style, RD_STATE_HOVER, &(rd_style){.background = rd_hex(0x252c3d)});
rd_class_set_state(ctx, button_style, RD_STATE_DISABLED, &(rd_style){.opacity = rd_num(0.4f)});

rd_node ok = rd_node_create(ctx);
rd_node_append(ctx, root, ok);
rd_node_add_class(ctx, ok, button_style);
rd_node_add_class(ctx, ok, primary);  // later classes win: the background is primary's

const rd_style* s = rd_node_computed_style(ctx, ok);
// background from primary (the later class), padding from button_style (primary doesn't set it)

Precedence

For each property, the last of these that sets it wins:

  1. Defaults (the reference’s Default column).
  2. The parent’s computed value, for inherited properties.
  3. Class base styles, in the order the classes were added.
  4. Class state variants for the node’s current states, ordered by state: hover, checked, focus_within, focus, focus_visible, active, disabled. Within one state, later classes win.
  5. The inline style.

Inline styles beat every class and every state variant. Put anything that should change on hover in a class, not inline.

States

raydom sets hover, active, focus, focus_visible and focus_within from input. checked and disabled are set by the application, or by a control such as an extras checkbox.

rd_node_set_states(ctx, ok, RD_STATE_HOVER, true);
// the hover variant of button_style now beats primary's base background

A disabled node and its descendants receive no pointer down, up or click events and can’t be focused. Hover and pointer move still apply.

focus_visible is set when focus came from the keyboard, or when the focused node is a text input. Use it, not focus, for focus rings.

Shared states

A control is usually several nodes: a checkbox is a row holding a box and a label. Its box should look hovered while the pointer is anywhere on the row, like CSS’s .row:hover .box. rd_node_set_share_states does that: the node’s class variants also apply for its parent’s states, and the sharing chains through parents that share too.

rd_node_set_share_states(ctx, box, true);   // box variants see the row's hover, checked, focus...
rd_node_set_share_states(ctx, mark, true);  // and the mark inside the box, through it
rd_node_set_states(ctx, row, RD_STATE_CHECKED, true);

Only class variants see shared states; rd_node_states still returns the node’s own.

Inheritance

rd_node child = rd_node_create(ctx);
rd_node_append(ctx, node, child);
rd_node_merge_style(ctx, node, &(rd_style){.color = rd_hex(0xe4e7ee), .font_size = rd_px(18)});
// child's computed color and font_size come from node; its background doesn't

Inherited properties: color, font, font_size, line_height, white_space, user_select, pointer_events, caret_color, selection_color, text_align. The rest start from the default on every node.

Computed styles

rd_node_computed_style returns the fully resolved style, with every field set. It computes styles if they are dirty. The pointer is valid until the next node is created.

Layout

Every node is a flex container by default, with flex_direction: column, align_items: stretch, and flex_shrink: 0. Children stack vertically and fill the width. Set display to RD_DISPLAY_GRID for grid, or RD_DISPLAY_NONE to remove a node from layout, drawing and hit-testing.

Sizes are border-box: width includes padding and border.

Flexbox

// A toolbar: fixed-width side items and a flexible middle.
rd_node bar = add(ctx, root,
                  (rd_style){.flex_direction = RD_FLEX_ROW,
                             .align_items    = RD_ALIGN_CENTER,
                             .column_gap     = rd_px(8),
                             .padding        = rd_edges_all(rd_px(8)),
                             .height         = rd_px(48)});
rd_node left   = add(ctx, bar, (rd_style){.width = rd_px(80), .height = rd_px(32)});
rd_node middle = add(ctx, bar, (rd_style){.flex_grow = rd_num(1), .flex_basis = rd_px(0), .height = rd_px(32)});
rd_node right  = add(ctx, bar, (rd_style){.width = rd_px(80), .height = rd_px(32)});

The algorithm follows CSS Flexible Box Layout §9, with these differences:

  • flex_shrink defaults to 0. Items keep their size and overflow unless they opt in to shrinking.
  • flex_direction defaults to column.
  • min_width and min_height auto resolve to 0, not to the content size. An item is never smaller than its padding plus border.

flex_basis: 0 with flex_grow: 1 splits free space without regard to content, which is the common “fill the rest” pattern.

Grid

rd_track  cols[3] = {rd_track_of(rd_px(200)), rd_track_of(rd_fr(1)), rd_track_of(rd_fr(2))};
rd_node   grid    = add(ctx, root,
                        (rd_style){.display               = RD_DISPLAY_GRID,
                                   .grid_template_columns = rd_tracks_create(ctx, cols, 3),
                                   .grid_auto_rows        = rd_track_of(rd_px(40)),
                                   .column_gap            = rd_px(10),
                                   .row_gap               = rd_px(10)});
rd_node header = add(ctx, grid, (rd_style){.grid_column_start = rd_line(1), .grid_column_end = rd_line(-1)});
for (int i = 0; i < 6; i++) add(ctx, grid, (rd_style){0});  // auto-placed, row by row

Track lists are interned: rd_tracks_create copies the array into the context and returns a handle that styles refer to. The list lives until the context is destroyed. C++ builds them with ctx.tracks({200_px, 1_fr, 2_fr}) and rd::repeat(3, {1_fr}).

A track is {min, max}. rd_track_of(v) uses v for both, except fr, which becomes minmax(auto, fr) as in CSS. rd_track_minmax builds any other pair.

Placement uses grid_{column,row}_{start,end}: rd_line(n) is a 1-based line, negative from the end of the explicit grid; rd_span(n) spans tracks. Items without placement are auto-placed in grid_auto_flow order into implicit tracks sized by grid_auto_rows and grid_auto_columns.

The algorithm follows CSS Grid §11. Named lines, named areas and dense packing are not implemented.

Auto-repeated tracks

// Responsive cards: as many columns of at least 260px as fit, sharing the rest.
rd_track card  = rd_track_minmax(rd_px(260), rd_fr(1));
rd_node  cards = add(ctx, root,
                     (rd_style){.display               = RD_DISPLAY_GRID,
                                .grid_template_columns = rd_tracks_create_auto(ctx, RD_REPEAT_AUTO_FILL, &card, 1),
                                .column_gap            = rd_px(20),
                                .row_gap               = rd_px(20)});
for (int i = 0; i < 5; i++) add(ctx, cards, (rd_style){.height = rd_px(120)});

rd_tracks_create_auto is CSS’s repeat(auto-fill, ...) and repeat(auto-fit, ...): the list repeats as many times as fits the grid’s content width, so the column count follows the window. Each track counts at its max size when that’s a length, else its min size, which is why minmax(260px, 1fr) means “at least 260px”. Without a definite width, the grid’s max width decides, then its min width; otherwise the list appears once.

  • RD_REPEAT_AUTO_FILL keeps empty repetitions: three cards in a four-column row leave a gap.
  • RD_REPEAT_AUTO_FIT drops repetitions no item occupies, so the cards stretch to fill the row.

The whole list repeats; fixed tracks before or after a repeat aren’t supported. C++: ctx.tracks(rd::repeat(rd::auto_fill, {rd::minmax(260_px, 1_fr)})).

Track lists are interned: creating a list identical to an existing one returns the same handle, so code that rebuilds lists doesn’t grow memory.

Absolute positioning

rd_node badge = add(ctx, bar,
                    (rd_style){.position = RD_POSITION_ABSOLUTE,
                               .inset    = {.top = rd_px(-6), .right = rd_px(-6)},
                               .width    = rd_px(12),
                               .height   = rd_px(12)});

An absolute node is positioned against its parent’s padding box using inset. With both insets on an axis and no size, it stretches between them. It takes no space in the parent’s flex or grid layout.

Scrolling

rd_node list = add(ctx, root, (rd_style){.height = rd_px(200), .overflow_y = RD_OVERFLOW_SCROLL});
for (int i = 0; i < 50; i++) add(ctx, list, (rd_style){.height = rd_px(24)});
rd_ctx_layout(ctx, 800, 600);
rd_node_set_scroll(ctx, list, 0, 300);  // clamped to the content: at most 50 * 24 - 200

overflow_x and overflow_y set to RD_OVERFLOW_HIDDEN clip children; RD_OVERFLOW_SCROLL also makes the node scroll with the wheel. The wheel scrolls the nearest scroll container under the pointer that can move in the gesture’s direction; once a gesture starts, it stays with that container until the wheel pauses.

A SCROLL axis whose content overflows shows a scrollbar. Bars draw over the content’s edge, inside the padding box, and take no layout space, so content doesn’t reflow when one appears. Dragging the thumb scrolls; pressing the track pages toward the pointer. Presses on a bar never reach the content under it.

rd_node_merge_style(ctx, list, &(rd_style){
    .scrollbar_width = rd_px(6),                     // 0px hides the bars; scrolling still works
    .scrollbar_color = rd_rgba(255, 255, 255, 60),   // inherited, so set it once on the root for a theme
});

Leave room with padding if content shouldn’t sit under the bar.

Layout hooks

Layout hooks run after every layout, with that layout’s geometry and scroll offsets. They’re for content that depends on its own geometry: a virtualized list binding the rows that scrolled into view, a chat log staying scrolled to its end. If hooks change the tree, layout runs once more before rd_ctx_layout returns, so the change shows in the same frame; hooks don’t run for that second pass.

rd_node_on_layout(ctx, node, fn, data, destroy) ties a hook to a node: destroying the node removes the hook and runs destroy(data), and the hook is skipped while the node is detached. That’s the right lifetime for a hook that belongs to a view, and it can’t leak. C++: node.on_layout([&] { ... }). rd_ctx_on_layout adds a hook for the context’s whole lifetime.

static void stick_to_bottom(rd_ctx* ctx, void* data) {
  rd_node log = *(rd_node*)data;
  rd_node_set_scroll(ctx, log, 0, 1e9f);  // clamped to the content just laid out
}

static rd_node log_node;  // the hook's data must live as long as the hook
rd_node_on_layout(ctx, log_node, stick_to_bottom, &log_node, NULL);  // removed with the log

Text and fonts

Fonts

rd_font body = rd_font_load_file(ctx, FONT_PATH);  // the first font loaded is the default
rd_font mono = rd_font_load_file(ctx, FONT_PATH);  // stands in for a second font file
if (body.id == 0) return 1;                        // a null handle means the file couldn't be loaded

rd_node code = rd_node_create(ctx);
rd_node_set_style(ctx, code, &(rd_style){.font = mono, .font_size = rd_px(13)});  // inherited by the text inside
rd_node_append(ctx, root, code);

rd_font_load takes TrueType or OpenType data in memory. With copy = false the data must outlive the context; with true raydom copies it. rd_font_load_file reads and copies a file. Both return a null handle (id == 0) on failure. The first font loaded becomes the default; rd_ctx_set_default_font changes it. In a style, (rd_font){0, true} means “the default font”.

font and font_size are inherited, so setting them on a container applies them to all the text inside it. Glyphs are rasterized on demand into an atlas per font size and display scale.

Text nodes

rd_node para = add_text(ctx, root, (rd_style){.color = rd_hex(0xe4e7ee), .line_height = rd_num(1.4f)},
                        "Text wraps on spaces to the width its container gives it.");
rd_node_set_text(ctx, para, "New text; the next layout re-measures it.", RD_TEXT_NUL);
size_t      len;
const char* now = rd_node_text(ctx, para, &len);

rd_node_set_text makes the node a text leaf and copies the UTF-8 string. Pass a length, or RD_TEXT_NUL for a NUL-terminated string. A text node’s size comes from its text; it lays out no children. rd_node_text returns the stored text, or NULL for a node that isn’t a text leaf.

line_height accepts rd_num (a multiple of font_size), rd_px, or rd_pct (of font_size).

Highlights

Measuring

Selection

Dragging over text whose user_select is auto (the default) selects it across text nodes, in tree order. The selection is also settable from code:

rd_ctx_select(ctx, para, 0, para, 8);
char   buf[64];
size_t n = rd_ctx_selection_text(ctx, buf, sizeof buf);  // "New text"

Offsets are bytes. rd_ctx_selection_text writes the selected text, one line per text node, and returns its full length, so a first call with buf = NULL sizes the buffer. RD_EVENT_SELECTION_CHANGE fires on the root when the selection changes. Set user_select: none on buttons and labels that shouldn’t start a selection.

Images

Loading

rd_image logo = rd_image_load_file(ctx, "logo.png");  // or rd_image_load(ctx, bytes, size) for #embed data
if (logo.id == 0) {
  // missing or unreadable file: fall back to generated pixels
}

raydom decodes PNG, JPEG, BMP, GIF (the first frame), TGA and PSD with a vendored copy of stb_image, so the formats don’t depend on how raylib was built. SVG is covered below. Decoding happens at load; the texture is created on the first draw. Loading and layout therefore work before InitWindow and in headless tests.

For a single binary, embed the file and load it from memory:

static const unsigned char logo_png[] = {
#embed "logo.png"
};
rd_image logo = rd_image_load(ctx, logo_png, sizeof logo_png);

Pixels generated by the program work the same way:

int            w = 64, h = 32;
unsigned char* rgba = calloc((size_t)w * (size_t)h, 4);
for (int i = 0; i < w * h; i++) rgba[i * 4 + 0] = rgba[i * 4 + 3] = 255;  // opaque red
rd_image swatch = rd_image_from_pixels(ctx, rgba, w, h);                 // copied; rgba can be freed
free(rgba);

SVG

rd_image_load and rd_image_load_file recognize SVG documents by their content and parse them with a vendored copy of nanosvg. An SVG’s natural size comes from its width and height, or its viewBox. It is rasterized when drawn, at the size it’s drawn at times the display scale, so it stays sharp at any size; when drawn larger later, it’s rasterized again. Smaller uses sample the larger raster.

rd_image icon = rd_image_load(ctx, icon_svg, sizeof icon_svg - 1);
rd_node  n    = rd_node_create(ctx);
rd_node_set_image(ctx, n, icon);
rd_node_set_style(ctx, n, &(rd_style){.height = rd_px(20), .color = rd_hex(0x5b8cff)});  // 20px, blue

An SVG that uses currentColor is drawn tinted by the node’s color, which is inherited, so icons match the text around them. The tint applies to the whole icon: in an SVG that mixes currentColor with other colors, the other colors are tinted too. Monochrome icon sets (Lucide, Heroicons, Feather) work as intended.

nanosvg covers paths, basic shapes, strokes, fills, opacity and gradients. It doesn’t support text, filters, masks, clip paths, patterns or embedded images. See Limits.

Changing and freeing

unsigned char frame[16 * 16 * 4] = {0};
rd_image_update(ctx, swatch, frame, 16, 16);  // a new size: nodes showing it relayout
rd_image_unload(ctx, logo);                   // safe on a null image

rd_image_update replaces the pixels, for video frames, emulator screens or anything drawn on the CPU. The texture is updated in place when the size is unchanged. rd_image_unload frees the pixels and texture; nodes showing the image collapse and draw nothing. Image handles aren’t reused, so a stale handle stays null. Everything is freed with the context.

Textures get mipmaps and trilinear filtering, so images stay smooth when drawn smaller than their size.

Events

Listeners

item.on_click([&] { log.push_back("item"); });                                  // bubble phase, target
list.on(RD_EVENT_CLICK, [&](rd::Event&) { log.push_back("list bubble"); });     // after the target
list.on(RD_EVENT_CLICK, [&](rd::Event&) { log.push_back("list capture"); }, true);  // before the target

The C form is:

rd_listener l = rd_node_on(ctx, node, RD_EVENT_CLICK, on_click, data, free_data, 0);  // or RD_LISTEN_CAPTURE
rd_node_off(ctx, l);                                                                   // runs free_data

fn(ctx, ev, data) receives the event. destroy(data) runs when the listener is removed, or when its node is destroyed. C++ listeners take rd::Event& or nothing; the callable is owned by the listener.

Propagation

Dispatch follows the DOM. The path from the root to the target is fixed when dispatch starts. Capture listeners run from the root down to the target’s parent, then the target’s listeners run (its capture listeners first), then bubble listeners run from the parent up to the root. ev->phase says which phase is running; ev->current is the node whose listener is running and ev->target is the node the event is for.

CallEffect
rd_event_stop_propagationFinish the current node’s listeners, then stop
rd_event_stop_immediate_propagationStop now; later listeners on the same node don’t run
rd_event_prevent_defaultSkip raydom’s default action (scroll, focus, editing, click)
 
rd::Node row = ctx.create(rd::Style().height(30_px));
row.on_click([](rd::Event& e) {
  e.stop_propagation();       // no bubble listeners run; capture listeners already have
  e.current().destroy();      // safe during dispatch: freed when dispatch ends
});
list.append(row);

Stopping at the target doesn’t undo capture listeners that already ran on ancestors.

Pointer capture

});

While a node holds the capture, every pointer event goes to it, wherever the pointer is, until all buttons are released or rd_node_release_pointer_capture is called. Use it for drags, sliders and splitters.

Overriding defaults

Firing events

rd_node_dispatch(ctx, node, type) fires an event through capture, target and bubble like any other, with the current pointer position and modifiers. Components use it to announce their own INPUT and CHANGE, so applications listen to them the same way as to built-in inputs. It returns false if a listener called rd_event_prevent_default.

Hit-testing

rd_node_at(ctx, x, y) returns the topmost node under a point after layout. Nodes with pointer_events: none are skipped, and children inherit it unless they set auto. Use none for overlays and decorative layers that shouldn’t take the pointer.

Cursors

The cursor style property sets the mouse cursor over a node. It’s inherited, so setting it on a card applies to everything inside. rd_update shows the cursor of the hovered node, or of the node holding the pointer capture.

rd::Class grip = ctx.create_class(rd::Style().cursor(RD_CURSOR_EW_RESIZE));
grip.on(RD_STATE_ACTIVE, rd::Style().cursor(RD_CURSOR_MOVE));  // while pressed, for the whole drag

RD_CURSOR_AUTO, the default, shows:

  • text over inputs, and over text whose user_select is auto;
  • pointer over nodes with the link role;
  • default over everything else, including text inside a button or other interactive role.

While the user drags a text selection, the cursor stays text even over other nodes. RD_CURSOR_NONE hides it. rd_ctx_cursor returns the resolved cursor, for applications that drive input themselves. Don’t call raylib’s SetMouseCursor alongside rd_update; set the style instead.

Mutating during dispatch

Listeners may create, move and destroy nodes, including the target and the current node. A node destroyed during dispatch is detached at once and freed when dispatch ends, so ev->current stays valid until the listener returns. A listener added to a node while that node’s listeners are running doesn’t run for the current event.

Focus, keyboard and text input

Focus

A node can take focus when its focusable is TAB (pointer, code and Tab) or POINTER (pointer and code). Inputs and nodes with an interactive role, such as buttons from rd_node_create_button, are focusable without the style. Pressing the primary button focuses the target or its nearest focusable ancestor, and clears focus if there is none. A listener that calls rd_event_prevent_default on POINTER_DOWN keeps focus where it was.

rd::Class button_style = ctx.create_class(rd::Style().padding(6_px, 12_px));
button_style.on(RD_STATE_FOCUS_VISIBLE, rd::Style().box_shadow(0, 0, 0, rd::rgba(91, 140, 255, 200), 2));
rd::Node save  = ctx.create_button("Save").add_class(button_style);  // focusable by role
rd::Node badge = ctx.create(rd::Style().focusable(RD_FOCUSABLE_TAB));  // any node, by style
int      saves = 0;
save.on_click([&] { ++saves; });  // also fires on Enter or Space while focused

Tab and Shift+Tab move through TAB nodes in tree order, wrapping, skipping hidden and disabled subtrees. rd_node_focus(ctx, node) focuses from code; a null node clears focus. rd_ctx_focus_next steps like Tab. A focus change fires BLUR, FOCUS_OUT, FOCUS, FOCUS_IN, in that order.

rd_ctx_set_focus_scope(ctx, node) keeps Tab and Shift+Tab inside a subtree, as a modal dialog needs; null restores the whole tree, and so does destroying the scope node. Pointer and programmatic focus aren’t restricted.

Enter and Space on a focused node that isn’t an input fire CLICK, so keyboard users can activate buttons without extra code.

Keyboard

ctx.root().on(RD_EVENT_KEY_DOWN, [&](rd::Event& e) {
  if (e.key() == RD_KEY_ESCAPE) ctx.blur();
});

Keys go to the focused node, or the root when nothing has focus, and bubble. ev->mods is a mask of RD_MOD_SHIFT, RD_MOD_CTRL, RD_MOD_ALT, RD_MOD_SUPER. Calling rd_event_prevent_default in a KEY_DOWN listener suppresses Tab navigation, activation, and editing for that key.

Text inputs

Setting a role

RD_ROLE_AUTO, the default, derives the role from the node: multi-line or single-line text input for inputs, text for other text leaves, canvas for nodes with a paint callback, and generic otherwise. rd_node_role returns the resolved role. Setting RD_ROLE_AUTO returns a node to its derived role.

The roles are a subset of AccessKit’s: generic, group, button, link, checkbox, radio button, radio group, switch, slider, text, label, heading, text input, multi-line text input, list, list item, image, canvas, menu, menu item, combo box, dialog, tooltip. More can be added in a minor release.

Focus

Interactive roles (button, link, checkbox, radio button, switch, slider, menu item, combo box) take focus without a focusable style, as inputs do:

  • Tab reaches them, unless their focusable is POINTER, which keeps pointer focus and skips Tab.
  • Enter and Space on a focused one fire CLICK, as for any focused node that isn’t an input.
  • To take one out of focus and pointer input, set RD_STATE_DISABLED on it.

Roles carry no other behavior. A checkbox doesn’t toggle itself; the application tracks its state and styles it.

Animation

Transitions

A node with a transition_duration animates its own style changes: a class added or removed, a state variant applying, an inline style set. Each changed property moves from the value it shows to its new value.

rd_class card = rd_class_create(ctx, &(rd_style){.width               = rd_px(200),
                                                 .background          = rd_hex(0x1a1f2b),
                                                 .transition_duration = rd_ms(200),
                                                 .transition_easing   = RD_EASING_EASE_OUT});
rd_class_set_state(ctx, card, RD_STATE_HOVER,
                   &(rd_style){.width = rd_px(240), .background = rd_hex(0x252c3d)});  // both animate
PropertyMeaning
transition_durationSeconds: rd_ms(150), rd_s(0.2); C++ 150_ms. 0, the default, changes at once
transition_delaySeconds before the change starts animating
transition_easingLINEAR, EASE (default), EASE_IN, EASE_OUT, EASE_IN_OUT: the CSS curves
transition_propertiesA mask of groups: COLOR, OPACITY, SHADOW, RADIUS, SIZE, SPACING, INSET, TEXT; all by default

Put the transition properties on the base style of a class, so they apply in every state. A variant that sets a different duration applies it to changes made while the variant is active.

What animates

  • Lengths (sizes, spacing, insets, gaps, radii, font size, line height, flex factors) when both values have the same unit. px to px animates; px to percent, or anything to auto, changes at once.
  • Height to and from auto. Collapsing from auto starts at the laid-out height. Expanding to auto animates to the content’s height, measured every frame, and ends as auto, so the node keeps following its content.
  • Colors, in premultiplied alpha, so fading to or from transparent doesn’t pass through black.
  • Edges, corners and shadows, side by side.

Everything else (display, flex_direction, fonts, enumerations) changes at once. A node’s first style never animates, nor does a change while the node has display: none.

Layout

Layout properties animate through layout: every frame of a width or margin transition lays the tree out again, so siblings and parents move with it, and hit-testing, anchoring and scrolling all follow. Layout is cached per node, so only the animating node’s ancestors and the siblings it moves are recomputed.

To move something without moving its neighbors, animate inset on a node with the default position: relative: it’s offset from where it was laid out, and nothing else reflows.

Accordions

rd_node_append(ctx, rd_ctx_root(ctx), toast);
// In: from transparent and 24px lower, to its place.
rd_node_animate(ctx, toast, &(rd_style){.opacity = rd_num(0), .margin.top = rd_px(24)},
                &(rd_style){.opacity = rd_num(1), .margin.top = rd_px(0)}, 0.2, RD_EASING_EASE_OUT, NULL, NULL);
// ... later, out: fade, then remove it when the animation ends.
rd_node_animate(ctx, toast, NULL, &(rd_style){.opacity = rd_num(0)}, 0.15, RD_EASING_EASE_IN, remove_node, &toast);

rd_node_animate merges to into the node’s inline style and animates the properties it sets, from what the node shows, over the given seconds and easing, whatever the node’s transition properties say. from sets starting values for some properties, which is how a node that was just created animates in. done runs once the time is up; it’s a timer, so it may destroy the node.

C++: node.animate(to, 0.2), node.animate(from, to, 0.2), and node.animate(to, 0.15, RD_EASING_EASE_IN, [&] { ... }).

Clock and frames

Animations advance in rd_ctx_layout, on the context’s clock (rd_ctx_set_time, which rd_update sets from raylib). rd_ctx_animating is true while anything moves. With rd_set_event_waiting, frames keep running while anything animates and wait for input once everything is still.

Animating layout costs one layout pass per frame for the animating parts of the tree, which is the same cost as resizing the window.

Overlay and anchoring

Menus, popovers, tooltips and modals have to draw above everything else and must not be clipped by the scroll container their trigger sits in. raydom provides two primitives for them: the overlay layer, and anchored positioning.

The overlay

rd_node menu = rd_node_create(ctx);
rd_node_set_style(ctx, menu, &(rd_style){.position = RD_POSITION_ABSOLUTE, .width = rd_px(160), .height = rd_px(90)});
rd_node_append(ctx, rd_ctx_overlay(ctx), menu);
rd_node_set_anchor(ctx, menu, &(rd_anchor){.node = button, .offset = 4});  // below the button

rd_ctx_overlay returns the overlay node, creating it on first use. It is a child of the root with special rules:

  • Always last. It stays the root’s last child: appending to the root inserts before it. So it draws after, and is hit-tested before, everything else.
  • Never clipped. It always covers the root, and no other node is its ancestor, so overflow containers don’t clip what’s inside it. Its position, inset, margin and size can’t be changed by styles; padding, background and layout properties can.
  • Transparent to input. The overlay node itself is never a hit target, so it doesn’t block the page under it. Only its children take input.

Overlay children are ordinary nodes. Give them position: absolute, or they stack in the overlay’s flex layout. Events from them bubble through the overlay to the root, and they’re in Tab order after the page.

Anchoring

rd_node_set_anchor positions a node against another node, or a point, after every layout:

rd_node_set_anchor(ctx, menu, &(rd_anchor){.node = button, .side = RD_SIDE_RIGHT, .align = RD_ALIGN_CENTER});
rd_node_set_anchor(ctx, menu, &(rd_anchor){.x = 300, .y = 200});  // at a point: a context menu
rd_node_set_anchor(ctx, menu, &(rd_anchor){.node = button, .match_width = true});  // a dropdown
FieldMeaning
nodeThe anchor node; null to use x, y in root coordinates
sideBOTTOM (zero), TOP, RIGHT or LEFT of the anchor
alignSTART (zero), CENTER or END along that side
offsetGap between the anchor and the node
no_flipKeep side even when the node only fits on the opposite side
no_shiftDon’t slide the node to keep it inside the root
match_widthLay the node out at the anchor’s width

A zero-initialized rd_anchor places the node below its anchor, start-aligned, flipping to the other side when it doesn’t fit and shifting to stay inside the window:

rd_node_merge_style(ctx, button, &(rd_style){.margin.top = rd_px(560)});
rd_ctx_layout(ctx, 800, 600);
rd_side side = rd_node_anchor_side(ctx, menu);  // RD_SIDE_TOP: no room below, so it flipped

rd_node_anchor_side reports the side actually used, for drawing an arrow that points at the anchor.

The anchor is followed every layout, including when it scrolls. Anchored nodes are placed in the order they were anchored, so a submenu anchored to an item of an anchored menu lands next to the item’s final position. If the anchor is destroyed or detached, the node stays where it was last placed.

Opening and closing

The overlay has no notion of open or closed. Show and hide popups with display, or create and destroy them:

rd_node_set_style(ctx, menu, &(rd_style){.position = RD_POSITION_ABSOLUTE, .display = RD_DISPLAY_NONE});  // close
rd_node_destroy(ctx, menu);                                                                           // or remove

Light dismiss, closing when the user presses outside, is a capture listener on the root:

ctx.root().on(RD_EVENT_POINTER_DOWN, [&](rd::Event& e) {
  if (!popover.contains(e.target()) && !toggle.contains(e.target())) hide(popover);
}, /*capture=*/true);

Canvases

A paint callback lets a node draw with raylib directly. The node is laid out and styled as usual; the callback draws inside its content box.

typedef struct chart {
  float values[5];
} chart;

static void paint_chart(rd_ctx* ctx, const rd_paint_info* info, void* data) {
  (void)ctx;
  const chart* c = data;
  rd_rect      r = info->content;  // screen coordinates, already scrolled
  rd_paint_scissor(info);          // clip to the visible part of the node
  float bar = r.width / 5;
  for (int i = 0; i < 5; i++) {
    float h = r.height * c->values[i];
    DrawRectangleRec((Rectangle){r.x + bar * (float)i + 4, r.y + r.height - h, bar - 8, h}, SKYBLUE);
  }
}

static chart data = {{0.2f, 0.5f, 0.9f, 0.4f, 0.7f}};
rd_node      plot = rd_node_create(ctx);
rd_node_set_style(ctx, plot, &(rd_style){.height = rd_px(240), .margin = rd_edges_all(rd_px(20))});
rd_node_set_paint(ctx, plot, paint_chart, &data, NULL);  // NULL: nothing to free when the node goes away
rd_node_append(ctx, rd_ctx_root(ctx), plot);

The callback runs inside rd_draw, after the node’s background and border and before its children, so children draw on top. raydom flushes raylib’s batch before the call, with no scissor or shader active.

rd_paint_info has:

FieldMeaning
contentThe node’s content box in screen coordinates, after scrolling
clipThe part of the screen left visible by enclosing overflow containers
dpiDevice pixels per logical pixel

rd_paint_scissor(info) clips raylib drawing to the content box within clip; raydom ends the scissor after the callback. Restore any other raylib state you change. Rendering to a texture with BeginTextureMode inside the callback is safe.

C++: node.paint([](const rd_paint_info& info) { ... }), with the callable owned by the node.

Pair a canvas with listeners on the same node for interaction: pointer events carry local_x and local_y relative to the node’s border box. Use the paint callback for drawing only; it must not change the tree.

The network view is built on this.

The C++ layer

<raydom/raydom.hh> wraps the C API in namespace rd. It is header-only, needs C++20, and doesn’t throw. Failures are reported the same way as in C: null handles and false.

Styles

rd::Style has one chainable setter per property, named as in the reference, plus overloads for common shapes:

using namespace rd::literals;

    .border_radius(6_px)                              // all corners

Callbacks

node.on(type, f, capture), node.on_click(f), node.paint(f) and node.measure(f) take any callable. The callable is moved into a heap allocation owned by raydom and deleted when the listener is removed or the node is destroyed. Captured references must outlive the node, or the listener must be removed first.

node.emplace_userdata<T>(args...) constructs a T owned by the node; node.userdata<T>() returns it.

The quickstart, annotated

#include <raydom/raydom.hh>
#include <raylib.h>

#include <string>

using namespace rd::literals;

int main() {
  SetConfigFlags(FLAG_WINDOW_HIGHDPI | FLAG_WINDOW_RESIZABLE);
  InitWindow(800, 600, "hello");
  {
    rd::Context ctx;
    ctx.load_font_file(FONT_PATH);  // any .ttf or .otf file

                                                  .padding(8_px, 16_px)
                                                  .border_radius(8_px)
                                                  .background(rd::hex(0x5b8cff))
                                                  .color(rd::hex(0xffffff)));
    button_style.on(RD_STATE_HOVER, rd::Style().background(rd::hex(0x7aa2ff)));

    int      clicks = 0;
    rd::Node label  = ctx.create_text("Clicked 0 times", rd::Style().color(rd::hex(0xe4e7ee)));
    rd::Node button = ctx.create_button("Click me").add_class(button_style);  // Tab focuses it; Enter and Space click it
    button.on_click([&] { label.text("Clicked " + std::to_string(++clicks) + " times"); });

    ctx.root()
        .style(rd::Style().padding(24_px).row_gap(12_px).align_items(RD_ALIGN_START))
        .append(button)
        .append(label);

    while (!WindowShouldClose()) {
      ctx.update();
      BeginDrawing();
      ClearBackground(BLACK);
      ctx.draw();
      EndDrawing();
    }
  }  // the context is destroyed here, before CloseWindow
  CloseWindow();
}
  • button_style is an rd::Class: a shared style, not a node. button_style.on(RD_STATE_HOVER, ...) is the C++ form of rd_class_set_state.
  • create_text(s, style) creates a text node. create_button(s, style) does the same with the button role, which makes it focusable and activatable with Enter and Space.
  • append returns the parent, so a subtree builds in one expression.
  • The lambda captures label by reference; both live in the same scope as the context.

Controls and toasts

raydom::extras has form controls (checkbox, switch, radio group, slider) and toasts. They are ordinary nodes built from core primitives, with a role, keyboard support and a default look, so they mix freely with your own nodes.

#include <raydom/extras/controls.hh>  // C: controls.h and toast.h

Events

A control fires RD_EVENT_CHANGE when the user changes it, and a slider also fires RD_EVENT_INPUT while it moves. Listen with rd_node_on or node.on; read the value with the getter. Setters (rdx_set_checked, rdx_radio_select, rdx_slider_set_value) fire nothing, so code that syncs a control from your model doesn’t loop.

To disable a control, set RD_STATE_DISABLED on it: it stops taking input and focus, and the theme dims it.

Checkbox and switch

rd::Node remember = rdx::checkbox(ctx, "Remember me");
rd::Node sync     = rdx::toggle_switch(ctx, "Sync");
rdx::set_checked(sync, true);  // setters don't fire CHANGE
bool remembered = false;
remember.on(RD_EVENT_CHANGE, [&] { remembered = rdx::checked(remember); });

Each is a row holding the box or track and an optional label. Clicking anywhere on the row, or Space or Enter while it has focus, toggles it. The row has RD_STATE_CHECKED while it’s on.

Radio group

rd::Node size = rdx::radio_group(ctx);
for (const char* s : {"Small", "Medium", "Large"}) rdx::add_radio(size, s);
rdx::radio_select(size, 1);
size.on(RD_EVENT_CHANGE, [&] { /* rdx::radio_selected(size) */ });

At most one option is selected; rdx_radio_selected returns its index, or -1. CHANGE fires on the group. Tab reaches the group once, at the selected option, and the arrow keys move the selection, wrapping and skipping disabled options, as in browsers.

Slider

rd::Node    volume = rdx::slider(ctx, {.min = 0, .max = 100, .value = 40, .step = 5});
std::string shown;
volume.on(RD_EVENT_INPUT, [&] { shown = std::to_string(static_cast<int>(rdx::slider_value(volume))); });  // while moving
volume.on(RD_EVENT_CHANGE, [&] { /* save it */ });  // drag released or key pressed

Dragging or pressing anywhere on the track moves it; the drag continues outside the slider. Arrow keys move one step (1% of the range when step is 0), Page Up and Page Down a tenth of the range, Home and End to the ends. A zero rdx_slider_desc is 0 to 100, continuous. The default width is 200px; set width on the slider to change it.

Menus, selects, modals and tooltips

These popups live in the overlay, use anchoring to sit next to what opened them, and share one set of dismissal rules:

  • A press outside closes the topmost menu or list; a press on the node that opened it doesn’t.
  • Escape closes the topmost popup.
  • Scrolling outside closes menus and lists.
  • Closing returns focus to the node that opened the popup, if focus was inside it.

rdx_popup_close(ctx, node) closes the popup any node belongs to, so a button inside a modal can close it.

#include <raydom/extras/popups.hh>  // C: popups.h

Menus

file.on_click([&] {
  rdx::menu(ctx, {{"New", "Ctrl+N"}, {"Open...", "Ctrl+O"}, {}, {"Quit", "Ctrl+Q"}},  // {} is a separator
            {.node = file.handle(), .offset = 4},                                       // below the button
            [&](int index) { log = "menu " + std::to_string(index); });
});

A menu takes a list of items: a label, an optional shortcut hint shown at the right (it doesn’t bind the key), and a disabled flag. An item with no label is a separator. The callback gets the index into the list of the chosen item, after the menu has closed, so it can open a modal or another menu. Dismissing the menu calls nothing.

The menu takes focus when it opens. Up and Down move through the enabled items and wrap, Home and End jump, Enter or Space chooses, and Tab closes the menu. Hovering an item highlights it.

Context menus

rdx::context_menu(area, {{"Copy", "Ctrl+C"}, {"Paste", "Ctrl+V", /*disabled=*/true}},
                  [&](int index) { log = "context " + std::to_string(index); });

rdx_context_menu_attach opens the menu at the pointer when the node is pressed with the secondary button. The items are copied, and the callback lives as long as the node.

Select

rd::Node theme = rdx::select(ctx, {"System", "Light", "Dark"}, "Theme");
theme.on(RD_EVENT_CHANGE, [&] { log = "theme " + std::to_string(rdx::selected(theme)); });

A select shows the chosen option, or the placeholder, with a chevron. Clicking it, or Enter or Space, opens a list as wide as the select, with the chosen option checked and focused; clicking the select again closes it. Up and Down on the closed select change the choice directly. CHANGE fires on the select when the user chooses; rdx::set_selected (rdx_select_set) doesn’t fire it.

Modals

rd::Node body = rdx::modal(ctx, {.title = "Rename", .on_close = [&] { log += ", closed"; }});
rd::Node name = ctx.create_input().placeholder("New name");
rd::Node done = ctx.create_button("Rename");
done.on_click([body] { rdx::close_popup(body); });
body.append(name).append(done);

A modal dims the window and centers a card with an optional title and × button. rdx::modal returns the card’s body, a column for your content and buttons. While it’s open:

  • Tab and Shift+Tab stay inside it (it sets the focus scope).
  • At the next clock update, focus moves to the first focusable node in the body, or the card.
  • Escape, the × button and a press on the backdrop close it, unless it’s persistent.

on_close runs whenever it closes, from any of those or from rdx_popup_close. width sets the card’s width (default 440px); the card never grows beyond the window and its body scrolls.

Tooltips

rdx::tooltip(file, "File operations");

The tooltip appears above the node, flipping below near the top edge, after the pointer rests on it for half a second, and at once when the node gets keyboard focus. Leaving, pressing, scrolling or blurring hides it. Attaching again replaces the text. The tooltip ignores the pointer, so it never covers what it describes.

Network view

raydom::extras provides rdx_graph, a view of nodes and edges for simulators and tools: lit 3D spheres, straight edges with optional arrows and labels, and messages drawn in flight. It is built on a canvas and lives in its own library so the core stays free of widgets.

target_link_libraries(your_app PRIVATE raydom::extras)

#include <raydom/extras/graph.hh>  // or graph.h for C

Creating a view

rd::Node   canvas = ctx.create(rd::Style().flex(1));
rdx::Graph graph  = rdx::Graph::create(canvas);
graph.background(rd::hex(0x0b0d12));
graph.label_class().set(rd::Style().font_size(12_px).color(rd::hex(0xe4e7ee)));
ctx.root().append(canvas);

rdx_graph_create(ctx, host) turns host into the view. The graph lives until the host node is destroyed; there is no separate destroy call. Node labels are text nodes under the host, styled with the class returned by label_class().

Nodes and edges

std::vector<rdx_node> nodes;
for (const char* name : {"A", "B", "C", "D", "E"}) nodes.push_back(graph.add_node({0, 0}, rd::hex(0x6c7385), name));

  graph.connect(nodes[i], nodes[(i + 1) % nodes.size()], {.color = rd::hex(0x2a3142), .width = 1.5f});

Positions are world units on a plane, y down. rdx_node and rdx_edge are generational handles, like rd_node. Removing a node removes its edges. fit(padding) frames every node; view(center, zoom) sets the camera.

The graph has no clock. Each frame, pass the messages in flight with their progress from 0 (at from) to 1 (at to); the call replaces the previous set.

float progress = t - static_cast<float>(static_cast<int>(t));  // your simulation decides this
graph.messages({{nodes[0], nodes[1], progress, rd::hex(0x5b8cff), 6}});

The showcase’s Network tab is a Paxos simulator built this way (examples/showcase/network.cc).

File dialogs

raydom::extras wraps the operating system’s file dialogs: Cocoa panels on macOS, the shell dialog on Windows, and xdg-desktop-portal on Linux, which shows the desktop’s own dialog (GNOME, KDE and others). The backends come from nativefiledialog-extended 1.4.1, vendored and compiled into raydom::extras, so applications still link one static library.

static void open_c(void) {
  const rdx_file_filter filters[] = {{"Text", "txt,md"}, {"Images", "png,jpg"}};
  const rdx_dialog_desc desc      = {.title = "Open", .filters = filters, .filter_count = 2};
  char*                 path      = NULL;
  switch (rdx_dialog_open(&desc, &path)) {
    case RDX_DIALOG_OK:
      printf("chose %s\n", path);
      rdx_dialog_free(path);
      break;
    case RDX_DIALOG_CANCEL:
      break;
    case RDX_DIALOG_ERROR:
      printf("dialog failed: %s\n", rdx_dialog_error());
      break;
  }
}

Each function writes paths that the caller owns: free one path with rdx_dialog_free, and the array from rdx_dialog_open_multiple with rdx_dialog_free_paths. Paths are UTF-8 on every platform.

Behavior

  • Blocking. Each call returns when the dialog closes. The raydom window doesn’t redraw meanwhile. Calling from a click listener is the usual pattern; the tree can be changed with the result before the listener returns.
  • Main thread. Call after InitWindow, on the thread that owns the window. macOS requires it.
  • Parent window. On macOS and Windows the dialog is attached to the raylib window. On Linux it isn’t, because raylib’s window handle there may be X11 or Wayland.
  • Unsupported builds. On the web, or with RAYDOM_FILE_DIALOG=OFF, every call returns RDX_DIALOG_ERROR with a message saying so. The API is always present, so code compiles everywhere.

Linux requirements

Building needs the libdbus development package (libdbus-1-dev on Debian and Ubuntu, dbus-devel on Fedora) and pkg-config. At run time, the desktop must provide xdg-desktop-portal, which current GNOME, KDE and most other desktops do. Set RAYDOM_FILE_DIALOG=OFF to build without either.

Limits

What raydom doesn’t do in this version. Behavior outside these limits is unspecified.

Layout

  • No display: block or inline; every container is flex or grid. Text nodes are leaves.
  • Grid: no named lines, no named areas, no dense auto-flow; an auto repeat must be the whole track list.
  • No position: fixed or sticky, and no z-index. Children draw in tree order, later siblings on top; content that must sit above everything goes in the overlay.
  • No aspect_ratio, no transform. Animate inset to move a node without reflowing its neighbors.
  • Transitions don’t animate width: auto, unit changes (px to %), or display; those change at once.
  • min_width/min_height auto is 0, not the content size.

Text

  • One font per text node. No rich text inside a node; use several text nodes in a row.
  • No shaping: no ligatures, no contextual forms, no bidirectional text. Pair kerning from the font is applied. Latin, Cyrillic, Greek and CJK display; Arabic and Indic scripts don’t shape correctly.
  • No hyphenation. Words longer than the line overflow.
  • No double- or triple-click word or line selection.

Input

  • No IME composition events. Text input is one codepoint at a time from raylib.
  • No touch or gesture input beyond what raylib reports as the mouse.
  • No accessibility tree.

Rendering

  • SVG: no text, filters, masks, clip paths, patterns or embedded images. Gradient coordinates written as unitless fractions (x2="1") render as a flat color; use percentages (x2="100%"). currentColor tints the whole SVG.
  • No background images; an image is its own node. Images are static (no GIF animation) unless updated with rd_image_update.
  • Shadows are outer box shadows only.
  • No gradients.

Threads

A context is single-threaded. Separate contexts on separate threads don’t share state, but raylib drawing must happen on the thread that owns the window.

Rules

  1. Create the context after InitWindow and destroy it before CloseWindow. In C++, scope rd::Context in a block that ends before CloseWindow.
  2. Load a font before creating text. There is no built-in font.
  3. Call rd_update before BeginDrawing and rd_draw between BeginDrawing and EndDrawing, once per frame.
  4. A new node is detached. Append it under rd_ctx_root(ctx) or a descendant, or it isn’t drawn.
  5. rd_style fields left out are unset, and unset fields fall through to classes, inheritance and defaults. Write &(rd_style){.width = rd_px(100)}. Never pass a computed style as an inline style: it sets every property and overrides all classes.
  6. The default flex_direction is column and the default flex_shrink is 0. Set flex_direction = RD_FLEX_ROW for rows. Set flex_shrink explicitly if items must shrink.
  7. Inline styles beat class state variants. Put hover, focus and active styling in classes.
  8. Lengths need units: rd_px(8), not 8. Unitless values (flex_grow, opacity, line_clamp, multiplier line_height) use rd_num.
  9. Grid track lists are handles: build them with rd_tracks_create (C) or ctx.tracks({...}) (C++).
  10. Handles are values. Store rd_node, not pointers. Check rd_node_alive when a node may have been destroyed.
  11. Listeners may mutate and destroy nodes, including their own node. A destroyed node is freed when dispatch ends.
  12. Geometry (rd_node_rect, rd_node_bounds) reflects the last layout. After building or changing the tree outside the frame loop, call rd_ctx_layout before reading it.
  13. The C++ layer doesn’t throw. Check returned handles and bool results where failure matters.
  14. raydom doesn’t own the main loop or the window. Time comes from rd_ctx_set_time, which rd_update calls; use rd_ctx_set_timer for delays, and rd_set_event_waiting rather than raylib’s EnableEventWaiting.
  15. Create controls with their role: rd_node_create_button / ctx.create_button for buttons, rd_node_create_input / ctx.create_input for inputs, rd_node_set_role for headings, lists, links and checkboxes. Don’t build a button from a plain node and a click listener; it gets no role and no default focus.
  16. Put menus, popovers, tooltips and modals in rd_ctx_overlay(ctx) with position: absolute, and position them with rd_node_set_anchor. Don’t place them inside the trigger’s subtree, where overflow containers clip them.
  17. For checkboxes, switches, radio groups, sliders, toasts, menus, selects, modals, tooltips, tabs, splitters, lists, tables and trees, use the extras components (rdx_checkbox_create, rdx_menu_open, rdx_list_create, …). Listen for RD_EVENT_CHANGE; restyle through rdx_theme(ctx). For more than a few hundred rows use rdx_list_create or rdx_table_create, which only create the rows in view. Build custom popups on the overlay only when the extras don’t fit.
  18. Animate with transition_duration on a class (it animates every style change, layout properties and height: auto included) or rd_node_animate for one-off motion. Don’t drive animations from timers by hand.

Minimal program

#include <raydom/raydom.h>
#include <raylib.h>

int main(void) {
  SetConfigFlags(FLAG_WINDOW_HIGHDPI | FLAG_WINDOW_RESIZABLE);
  InitWindow(800, 600, "hello");
  rd_ctx* ctx = rd_ctx_create();
  rd_font_load_file(ctx, FONT_PATH);  // any .ttf or .otf file

  rd_node card = rd_node_create_text(ctx, "Hello from raydom", RD_TEXT_NUL);
  rd_node_set_style(ctx, card,
                    &(rd_style){
                        .padding       = rd_edges_all(rd_px(16)),
                        .border_radius = rd_corners_all(rd_px(8)),
                        .background    = rd_hex(0x1a1f2b),
                        .color         = rd_hex(0xe4e7ee),
                    });
  rd_node_append(ctx, rd_ctx_root(ctx), card);

  while (!WindowShouldClose()) {
    rd_update(ctx);  // input, then layout at the window size
    BeginDrawing();
    ClearBackground(BLACK);
    rd_draw(ctx);
    EndDrawing();
  }
  rd_ctx_destroy(ctx);  // before CloseWindow, so GPU resources are released
  CloseWindow();
}

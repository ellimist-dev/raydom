raydom internals

Introduction

This book is for people changing raydom: how it is put together, why it is put together that way, and how to extend it without breaking the parts that depend on each other. The user book (docs/, published per release) describes what raydom does; this one describes how.

It tracks main. Where it names a function or a file, the name is real; where behavior is subtle, the chapter says which test pins it down.

What raydom is, structurally

  • A C23 core (src/, include/raydom/*.h): a retained tree of nodes, a style system, flexbox and grid layout, text shaping and wrapping, event dispatch, animation, and a renderer on raylib. One static library, raydom::raydom.
  • A C++20 layer (include/raydom/raydom.hh): header-only wrappers that add RAII for the context, builder-style styles, and lambda callbacks. No exceptions.
  • Extras (extras/): components built only on the public core API (controls, popups, views, toasts, a network view, native file dialogs), in a second library, raydom::extras.
  • Docs (docs/): the user book, whose code samples are programs compiled and run by the test suite.
  • The showcase (examples/showcase/): one application with a feature tour, a desktop messaging app and a Paxos simulation, used as the integration test you look at.

The first configure downloads raylib 6.0 into build/_deps. The tests and the showcase use a font from raylib’s examples (anonymous_pro_bold.ttf), which is why they need a downloaded raylib rather than an installed one.

Sanitizers are on by default

just build compiles the library, tests and examples with AddressSanitizer and UBSan. Most memory bugs in this codebase have surfaced as a sanitizer report in an ordinary test run, so leave them on while developing. Release builds and installs don’t use them; the flags are private to raydom’s targets.

Before sending a change

  1. just test: every test, including the documentation examples, passes.
  2. just lint: no new findings in the files you touched.
  3. just consumer if you changed CMake, headers, or anything that affects linking.
  4. If behavior changed, update the user book and, where relevant, this book. If a style property changed, the property reference regenerates from the source, but its description lives in docs/tools/preprocess.py.
  5. Look at the showcase for anything visual. Screenshots help in review; see below.

There is no CI for tests yet; the workflow in .github/ only publishes documentation. Run the suite locally.

Conventions

Naming

PrefixMeaning
rd_Public core API
RD_Public enumerators and macros
rd__Internal to the core, shared between core files (src/*_internal.h)
rdx_, RDX_Public extras API
rdx__Internal to extras (extras/src/extras_internal.h)
rd::, rdx::C++ layers

Everything else in a .c file is static. Internal headers are not installed.

Names are snake_case in C and C++. Types are lowercase (rd_node, rd_style). File-local types drop the prefix (vlist, popup).

Files

  • C sources are .c, C headers .h; C++ sources .cc, headers .hh.
  • One public header per subsystem; raydom.h includes them all.
  • A subsystem’s private interface goes in src/<name>_internal.h when more than one file uses it, otherwise it stays static.

Style

  • clang-format with the repository’s .clang-format. It sets no column limit; keep lines near 120 by hand.
  • Comments are few and say why, or what a reader can’t see from the code: invariants, units, ownership, the CSS section an algorithm follows. Don’t narrate code.
  • Public headers document each function in one or two lines above it: what it does, what it returns on failure, who owns what.

Errors

The core never aborts on bad input. A function that can fail returns false, a null handle, or does nothing, and says so in its header comment. Stale node handles are always safe to pass. Allocation failure is handled where it is reasonable to recover (a list that can’t grow keeps its old contents), and assert is reserved for invariants the library itself maintains.

The C++ layer never throws. It allocates callables with new (std::nothrow) and reports failure the same way as C. Code that builds with -fno-exceptions must keep building.

Ownership

  • The context owns everything created through it. rd_ctx_destroy frees it all, in a defined order (see The context and the tree).
  • Anything raydom keeps a pointer to has a destroy callback (rd_destroy_fn) next to it: userdata, listener data, measure and paint data, timer data, extension data.
  • Node userdata belongs to the application. Nothing in the core or extras may store its own data there; the showcase reads userdata on hovered nodes as its own type, and a component that wrote an index into it crashed it. Components keep state in their own tables (see Extras).

Tests

Every behavior change comes with a test. Tests are plain C or C++ programs using tests/check.h; see Writing tests.

Commits

Small, focused commits with a message that says what changed and why. Keep vendored code unmodified; upstream fixes instead (see Design decisions).

Platforms

  • The core uses only C23 and raylib, and builds wherever raylib does, including Emscripten.
  • The file dialog backend is Objective-C on macOS, so the top-level CMakeLists.txt enables OBJC right after project() when extras and dialogs are on. Enabling it inside extras/ fails (CMAKE_OBJC_COMPILE_OBJECT is missing for targets in that directory).
  • On Linux the dialog backend is xdg-desktop-portal over libdbus (pkg-config dbus-1). RAYDOM_FILE_DIALOG=OFF compiles a stub that returns errors, so the API stays available.

Options

RAYDOM_BUILD_EXTRAS, RAYDOM_FILE_DIALOG, RAYDOM_FETCH_RAYLIB, RAYDOM_INSTALL, RAYDOM_BUILD_TESTS, RAYDOM_BUILD_EXAMPLES, RAYDOM_SANITIZE. Tests, examples and install rules default to on only when raydom is the top-level project, so a project embedding it with FetchContent builds just the libraries.

Installing

RAYDOM_INSTALL=ON installs the libraries, headers (including the generated version.h) and a CMake package: raydomConfig.cmake calls find_dependency(raylib) and imports raydom::raydom and raydom::extras. The version file uses SameMinorVersion while the major version is 0 and SameMajorVersion after.

Platform libraries the extras need (AppKit, UniformTypeIdentifiers, ole32, dbus-1) are attached as plain link names, so they survive export without imported targets.

just consumer is the packaging test: it builds tests/consumer both ways and runs it.

Versioning

Semantic versioning; the version lives in project(raydom VERSION ...) and flows into version.h, the package version file and the docs. Before 1.0 a minor release may break the API, and changing the numeric value of a public enumerator counts as breaking.

The core is the only part that knows the private structures. Extras and the C++ layer use the public headers, so anything they need is something an application could need too; when extras needed per-context storage or a post-layout callback, those became public core features (rd_ctx_set_extension, rd_ctx_on_layout) rather than private back doors.

Only src/render.c calls raylib. Everything else is plain C, which is why layout, text, events and animation run headless in tests.

One frame

A raylib application calls rd_update, then rd_draw inside BeginDrawing/EndDrawing. Here is what happens, in order:

 │   ├─ rd__anim_tick             animations into computed styles
 │   ├─ rd_ctx_compute_styles     dirty subtrees only; starts transitions
 │   ├─ rd__layout_node(root)     flex and grid, with caches
 │   ├─ rd__place_anchored        overlay popups next to their anchors
 │   ├─ layout hooks              rd_ctx_on_layout callbacks
 │   └─ second pass               only if a hook dirtied the tree
 ├─ apply the mouse cursor

rd_draw

Each stage reads what the previous one produced and marks dirty flags for the next. Nothing is recomputed eagerly: mutating the tree or styles from a listener only sets flags, and the next rd_ctx_layout does the work once.

Data flow

The context and the tree

Slots and parallel arrays

rd_ctx (src/internal.h) stores nodes in parallel arrays indexed by slot:

ArrayElementContents
slotsrd_slotGeneration, flags, tree links, child count, userdata
stylesrd_node_styleComputed style, inline style, classes, states, animation
layoutsrd_node_layoutRect, insets, scroll, caches, measure/paint callbacks, anchor
eventsrd_node_eventsListeners

A node is a slot index plus everything at that index in each array. Splitting by subsystem keeps each pass’s data dense: layout walks slots and layouts and rarely touches events. Slot 0 is never used, so index 0 means “none” in tree links.

Tree links are indices (parent, first_child, last_child, next_sibling, prev_sibling), a doubly linked child list per node, so append, insert and detach are O(1) and nothing is ever reallocated per node.

Handles

rd_node is {index, gen}. Destroying a node clears its slot’s ALIVE flag and puts the slot on a free list; reusing the slot bumps its generation. Either way a stale handle stops matching. rd__slot(ctx, n) returns the slot only when the handle is live; every public function starts with it, which is why stale handles are safe everywhere.

The free list threads through next_sibling of dead slots, so it costs no extra memory.

Arrays grow by doubling. Code must not hold a pointer into ctx->slots (or any per-node array) across anything that can create a node; re-index after.

Mutation

rd_node_insert_before refuses cycles (walks up from the parent) and the root; moving a node unlinks it first. Every mutation marks dirty flags (rd__mark_layout_dirty, rd__mark_style_dirty) rather than recomputing.

The overlay is kept the root’s last child: inserting at the end of the root inserts before it. See Layout.

Destroying during dispatch

Listeners may destroy any node, including the one whose listener is running. While ctx->dispatch_depth is non-zero, rd_node_destroy detaches the node at once (so it stops being laid out, drawn and hit-tested) and pushes it on pending_destroy. When the outermost dispatch ends, flush_deferred destroys those that are still detached; one a later listener re-attached is spared. Listeners removed during dispatch are flagged and compacted at the same point. This is what makes ev->current valid for the whole listener call.

Extensions

rd_ctx_set_extension(ctx, key, data, destroy) stores one pointer per key, where the key is an address the caller owns. Extras keep their theme, registries and popup manager here; it’s a short linear list, looked up rarely.

Destruction

rd_ctx_destroy frees in an order chosen so callbacks see a consistent world:

  1. For every live slot: style, layout and event data (running measure, paint and listener destroy callbacks), then the userdata destroy callback. Slots keep their ALIVE flag during this loop, so a destroy callback that clears a timer or looks up a handle still works.
  2. Style storage and fonts.
  3. Layout hook destroy callbacks.
  4. Extension destroy callbacks, after the nodes, because extensions often hold state keyed by nodes.
  5. Images, then timers (running their destroy callbacks).
  6. GPU resources (only if the raylib window still exists) and event storage.

Destroy callbacks must not mutate the tree; they may free memory, clear timers, and read handles.

Styles

One list of properties

Every style property is one line of the RD_STYLE_PROPS(X) X-macro in include/raydom/style.h:

X(name, type, kind, inherited, affects_layout)

Everything that needs a per-property case expands this list instead of naming properties:

ExpansionWhereProduces
RD_STYLE_FIELD_style.hThe rd_style struct
MERGE_##kindstyle.crd_style_merge: copy set fields
EQ_##kind, style_diffstyle.cChange detection, flagged inherited and layout
SET_##kindstyle.c (debug)rd__style_check_defaults: the default style sets every field
inherited copy in buildstyle.cInheritance from the parent’s computed style
P_##name, PROPS[]anim.cProperty ids, offsets, sizes and kinds for transitions
RD_HH_SETTER_##kindraydom.hhOne chainable setter per property, plus overloads per kind

The kind says how a property is merged, compared and animated: VAL (rd_val), COLOR, EDGES, CORNERS, SHADOW, ENUM, TRACKS, TRACK, GRID_LINE, FONT. Adding a kind means adding a case to each expansion; adding a property of an existing kind is one line plus a default. See Adding a style property.

Zero means unset

Every field type reserves zero for “unset”: RD_UNIT_UNSET, enum value 0, rd_color.set == false, an rd_grid_line with kind 0. That single rule gives:

  • partial styles from designated initializers (&(rd_style){.width = rd_px(10)}),
  • rd_style_merge that copies only what’s set,
  • classes and variants that layer without knowing about each other.

The cost is that “the value 0” needs a unit or a set flag: rd_px(0) is set, {0} is not; transparent is rd_rgba(0,0,0,0) with set = true. default_style in style.c sets every field, which a debug-build assertion checks at context creation, so a new property without a default fails immediately.

Computing a style

build(ctx, i, parent, out):

  1. out = default_style.
  2. Copy inherited properties from the parent’s computed style.
  3. Merge each class’s base style, in the order classes were added.
  4. For each state bit in precedence order (bit order of rd_state), merge each class’s variant for that state. The states used are the node’s own, or’ed with its parents’ while share_states chains upward.
  5. Merge the inline style.

Then rd__transition (see Time) may replace animated properties with their current values, and the result is compared with the previous computed style.

Dirty tracking

  • RD_FLAG_STYLE_DIRTY on a node: its own inputs changed (inline style, classes, states, parent).
  • RD_FLAG_SUBTREE_STYLE_DIRTY on its ancestors: something below needs computing. rd__mark_style_dirty stops climbing at the first ancestor that already has it.

compute_rec walks from the root, descending only into subtrees flagged dirty, and recomputes flagged nodes. The diff decides what else happens:

  • any change: paint dirty;
  • a layout-affecting change: rd__mark_layout_dirty on the node;
  • an inherited change: children recompute even if not flagged.

State changes are cheap when nothing cares: rd_node_set_states marks the node dirty only if one of its classes has a variant for the changed state (and marks sharing children). Hovering over a tree of unstyled nodes recomputes nothing.

Changing a class (rd_class_set, rd_class_set_state) scans every slot for nodes using it: O(nodes), acceptable because classes change rarely, usually at startup.

Storage

  • Inline styles are heap-allocated per node only when set.
  • Classes live in ctx->classes for the context’s lifetime; a node keeps a small array of class ids.
  • Track lists are interned by content into an append-only pool: rd_tracks_create returns the existing handle for an identical list (including its repeat mode), so rebuilding lists is free. A style holds the handle by value, which is why lists can’t be freed or reference counted: raydom can’t see the copies in inline styles, classes and variants.

Computed style access

rd_node_computed_style computes pending styles first, then returns a pointer into ctx->styles, valid until the next node creation (which may reallocate the array). Internally, code reads ctx->styles[i].computed directly and must call rd_ctx_compute_styles first when it can run outside layout: rd_ctx_focus_next and rd_node_focus do, because a node created this frame has no computed focusable yet.

Layout

The measure contract

All layout goes through one function:

rd_size rd__layout_node(rd_ctx* ctx, uint32_t i, rd_layout_key k, bool perform);

rd_layout_key is the question asked of a node: available width and height, each with a mode, and the containing block size for percentages.

ModeMeaning
EXACTLYThe border box is this size
AT_MOSTFit content, up to this size
UNDEFINEDMax-content: size freely (available size is NaN)
MIN_CONTENTThe smallest size without overflow

With perform false it’s a measurement and returns a size; with perform true it lays out the subtree and sets child rects. A node’s own width, height, min_* and max_* are resolved by its parent (or the absolute or anchoring code) into the key; rd__layout_node itself answers for the content. Forgetting this in a new caller is the classic bug: a fixed-height node measured with AT_MOST reports its content height. Copy the resolution from rd__layout_absolute.

This is Yoga’s model: one recursive function, intrinsic sizes on demand, no separate pre-pass.

Caches

Each node keeps one layout entry (the last perform) and four measure entries (round robin), each keyed by rd_layout_key:

  • A hit returns the stored size without recursion. Flex and grid ask the same questions repeatedly (measure for basis, measure for cross size, then perform), so this is what keeps layout near-linear.
  • normalize_key drops the containing block from the key when the node has no percentage padding or min/max, and sets available sizes to NaN for UNDEFINED/MIN_CONTENT, so equivalent questions share an entry.
  • RD_FLAG_LAYOUT_DIRTY invalidates a node’s entries the next time it is asked anything. rd__mark_layout_dirty marks the node and every ancestor, without stopping early: subtrees layout never visits (display none, measured leaves, detached) keep stale flags, so an already-dirty node doesn’t prove its ancestors are.

The cost model: an unchanged frame is one perform call on the root that hits the cache. A change re-lays out the path to the root and whatever the changed sizes affect.

Flexbox

layout_flex follows CSS Flexbox §9: collect items (skipping absolute and display: none), resolve flex basis (measuring content when auto), break into lines when wrapping, resolve flexible lengths (§9.7, with min/max freezing), determine cross sizes and stretch, then justify and align. Differences from CSS are deliberate and documented for users: flex_direction defaults to column, flex_shrink to 0, and automatic minimum sizes are 0.

Grid

grid.c follows CSS Grid: placement (§8.5, sparse auto-placement over an occupancy map), then track sizing (§11): intrinsic contributions (§11.5) and fr expansion (§11.7), each axis sized against the other’s result. An indefinite axis is sized to content, clamped, and re-run at the clamped size when that differs. Named lines, named areas and dense packing aren’t implemented.

Auto repetition (§7.2.3.2): a list created with rd_tracks_create_auto is expanded per layout. repetitions computes the count from the content box (definite size, else max size, else the min size to reach, else one), with each track at its max size when that’s a length, else its min size. The expanded list replaces the explicit list before placement, so line numbers (including negative ones) refer to it. For auto-fit, collapse_empty removes the repeated tracks no item occupies after placement and renumbers later items. Removal is equivalent to CSS’s collapsing (zero size and merged gaps) because nothing spans those tracks, and it leaves track sizing untouched.

Text and measured leaves

A node with a measure callback is a leaf: layout_leaf calls measure_fn(data, w, wmode, h, hmode) with content box sizes. Text nodes, inputs and image nodes are measured leaves whose callbacks live in text.c and image.c; rd__is_text and rd__node_image identify them by comparing the callback pointer, so there’s no type field to keep in sync.

Absolute positioning

rd__layout_absolute positions an absolute child against its parent’s padding box after the flow pass, resolving inset, margins and the node’s own size (stretching between opposite insets when no size is set).

The overlay

rd_ctx_overlay creates a node that is the root’s last child. Its geometry is fixed during style computation: build forces position absolute, zero inset and margin, and auto sizes, whatever classes or inline styles say. So the overlay always covers the root, and layout needs no special case. Hit-testing skips the overlay node itself so it doesn’t block the page; its children are hit-tested first because it’s the last child.

Anchoring

rd__place_anchored runs after the main pass. For each node with an anchor, in the order they were anchored, it reads the anchor’s bounds from this layout, chooses a side (flipping when only the other side fits), aligns, shifts into the root, and writes the node’s rect relative to its parent. match_width re-lays out the node at the anchor’s width, resolving the node’s own height and bounds the way absolute layout does.

Placing after layout means anchoring never affects other nodes’ sizes, and a submenu anchored to an item of an anchored menu works because the menu was placed first.

Layout hooks and the second pass

Hooks are context-wide (rd_ctx_on_layout) or node-scoped (rd_node_on_layout). A node-scoped hook sets RD_FLAG_HAS_HOOK on its slot; freeing the slot drops its hooks. A hook can destroy its own node while hooks are running, so dropping only marks the hook dead, and sweep_hooks runs destroy callbacks and compacts the list after the run. The loop copies each hook before calling it because a hook may add hooks, reallocating the array. Hooks whose node is detached are skipped.

rd_ctx_layout runs the hooks after placing anchors. If any hook left the root dirty (layout or style), it runs one more pass. Hooks don’t run on that pass, which bounds the work at two passes per frame. Virtualized lists bind rows here; a hook that would need a third pass is doing something layout should do.

Scrolling

Scroll offsets live in rd_node_layout.scroll and are clamped to the content (rd_node_content_size: the padding box plus children’s margin boxes) during layout and whenever set. Offsets don’t dirty layout: drawing and hit-testing subtract them, so scrolling is cheap.

Natural height

rd__natural_height measures a node as if height were auto at its current width, for transitions to height: auto. It temporarily changes the computed height, measures, restores it, and marks the node dirty, because the measurement went into the caches under a key that doesn’t include style.

Text

Fonts

font.c wraps stb_truetype. A font is loaded once into the context (copied or borrowed), gets an id, and caches codepoint-to-glyph lookups and advances. Kerning comes from the font’s kern/GPOS pair tables. There is no shaping: no ligatures, contextual forms or bidirectional reordering. That’s the biggest limit of the text stack; see Known limits.

Text nodes

rd_node_set_text attaches an rd_text to the node as its measure data. It holds the UTF-8, the decoded codepoints, and byte offsets per codepoint.

Two caches sit in rd_text:

  • Tokens for the current font, size and white_space: words, spaces and newlines with widths. CJK characters are single-character words, which gives them a break opportunity on each side.
  • Lines for the last width: greedy breaking (break_lines) over the tokens. Trailing spaces belong to a line but hang outside its width; collapsible spaces at a line start are dropped.

Measuring (text_measure) runs line breaking at the available width, or with no limit for max-content; min-content is the widest word. line_clamp caps the measured line count; text_overflow adds the ellipsis when drawing.

Byte offsets are the public unit everywhere (selection, highlights, input carets) because applications index their own strings in bytes; codepoint indices stay internal.

Inputs

rd_node_make_input adds an rd__input to the text: anchor and caret (bytes), a goal column for vertical movement, horizontal scroll for single-line inputs, and undo/redo stacks of snapshots. Consecutive typing merges into one undo step. Inputs keep all whitespace regardless of style. Key handling (rd__input_key) runs as the default action of KEY_DOWN on a focused input, so a listener can prevent_default any key.

The document selection

selection.c keeps an anchor and focus (node and byte offset) across text nodes. Ordering across nodes uses a pre-order numbering computed lazily while a selection exists (rd__selection_prepare). Dragging maps the pointer to the nearest selectable text (vertical distance first), and copying collects the selected text one line per node.

Drawing text

Text is drawn by the renderer from the same line layout, glyph by glyph from the atlas (see Rendering), at baselines snapped to device pixels.

Events and input

Listeners and dispatch

Listeners are stored per node (rd_node_events) with an id, flags (capture) and a destroy callback. rd_node_off during dispatch flags the listener removed; storage is compacted when dispatch ends.

dispatch builds the path from the target to the root before calling anything, then runs capture listeners root-to-parent, the target’s capture listeners, the target’s bubble listeners, and bubble listeners up to the root. Fixing the path first means listeners can reshape the tree without changing who receives the event. Listeners added to a node during its own invocation don’t run for that event: invoke reads the count up front.

fire returns whether the default action was prevented; default actions (focus on press, scrolling, editing, Tab, Enter-to-click) run in the caller after dispatch, which is what makes rd_event_prevent_default work for all of them. rd_node_dispatch is fire made public, for components announcing INPUT and CHANGE.

Pointer

rd_ctx_pointer(x, y, buttons, wheel) is the only pointer entry point; rd_update feeds it from raylib. In order:

  1. Scrollbars first. scrollbar_pointer checks for a bar under the pointer on the nearest scroll container above the hit node, or an active bar drag. If it handles the pointer, the content sees nothing: no pointer events, no focus change, no selection.
  2. Hover. The hovered leaf is the hit node, or the pointer-capture node. update_hover diffs the old and new ancestor chains: POINTER_LEAVE deepest-first on nodes losing hover, POINTER_ENTER outermost-first on nodes gaining it, and RD_STATE_HOVER on the chain.
  3. Move. POINTER_MOVE, then input drag-selection or document drag-selection.
  4. Buttons. Per changed button: POINTER_DOWN (with RD_STATE_ACTIVE on the chain, and unless prevented, pointer focus and starting a selection), POINTER_UP, and CLICK on the common ancestor of the press and release targets for the primary button. ev->clicks counts clicks on the same node within MULTI_CLICK_SECONDS and MULTI_CLICK_SLOP; keyboard activation resets it to 1.
  5. Wheel. A gesture latches to the scroll container chosen at its start (wheel_latch) until the wheel pauses (LATCH_SECONDS) or the pointer moves, so a horizontal scroll inside a vertical list doesn’t get stolen halfway.

Disabled subtrees receive no down, up or click.

Focus

can_focus accepts inputs, interactive roles (button, link, checkbox, radio, switch, slider, menu item, combo box, tab, splitter) and nodes with focusable, if displayed and not disabled. Tab collects focusable nodes in tree order within the focus scope (rd_ctx_set_focus_scope). keyboard_modality records whether focus last moved by keyboard, which decides RD_STATE_FOCUS_VISIBLE. Focus changes fire BLUR, FOCUS_OUT, FOCUS, FOCUS_IN, after the states are set, so a FOCUS listener can read FOCUS_VISIBLE. A focused node that gets destroyed, detached, hidden or disabled loses focus silently (focus_valid).

Keyboard

rd_ctx_key dispatches KEY_DOWN/KEY_UP to the focused node or the root. Default actions, unless prevented: editing in an input, selection keys outside inputs, Tab navigation, and Enter or Space as CLICK on a focused non-input. rd_ctx_text dispatches TEXT and inserts into a focused input.

Cursors

rd_ctx_cursor resolves the cursor from state at the time it’s asked: a selection drag forces text; a scrollbar under the pointer forces default; otherwise the hovered node’s computed cursor, with AUTO resolved by role and content. rd_update applies it through raylib only when it changes.

Hit-testing

rd__hit walks the laid-out tree back to front (last child first), honoring clips, display: none, pointer_events: none, and skipping the overlay node itself. Measured leaves don’t hit-test their children.

Rendering

The display list

rd__display_list walks the laid-out tree and emits commands into a reusable array:

CommandDraws
SHADOWA blurred rounded box
RECTBackground and border of a box, rounded or not
TEXTA text node’s lines
PLACEHOLDERAn empty input’s placeholder
FILLA plain rectangle: selection, highlight, caret
CLIPSets the scissor; the enclosing clip is restored by a second CLIP
PAINTA canvas callback
IMAGEAn image placed by object_fit, with its source rectangle

The walk applies opacity multiplicatively down the tree, culls nodes outside the current clip, and draws scrollbars after a scroll container’s children. Commands carry everything the renderer needs except text layout and textures, which it reads from the context.

The list is rebuilt every rd_draw. That’s a deliberate simplicity: building it is a linear walk with no allocation in the steady state, much cheaper than the GPU work, and it means there’s no retained render state to invalidate.

Keeping the display list separate from raylib is also what lets tests/test_render.c check drawing headlessly.

The renderer

render.c executes commands with raylib and rlgl:

  • Rounded boxes and shadows use one fragment shader evaluating a signed distance to a rounded rectangle with per-corner radii and per-side borders, antialiased over one device pixel. Shadows are the same shape with a blur. Boxes without corner radii skip the shader and draw with raylib’s batched rectangles, borders included.
  • Pixel snapping. Rect edges and text baselines snap to device pixels (snap(v, dpi)), so borders and text stay crisp at fractional DPI.
  • Images draw with DrawTexturePro, or through the same shader in a textured mode when the box has radii, so rounded corners clip them.
  • Clipping is the GPU scissor, in screen pixels.
  • Canvases: PAINT flushes the batch, ends any scissor, calls the application’s callback with the content box and the clip, then restores state.

Glyph atlas

Text is drawn glyph by glyph from one 2048×2048 RGBA texture. Glyphs rasterize on first use (stb_truetype coverage into the alpha channel) at the device-pixel size, and are found in an open-addressing table keyed by font, size in quarter pixels and glyph. Packing is shelf-based; when the atlas fills, it’s cleared and refilled on demand. That favors simplicity over long-lived caching: a UI rarely shows more distinct glyphs than fit, and clearing is correct, just a hitch.

Images and SVG

Decoding (stb_image) and SVG parsing (nanosvg) happen in image.c at load, with no GPU, so image nodes lay out headlessly. The texture is created on first draw and the CPU pixels freed. SVGs keep their parsed form and rasterize in draw_image at the drawn size times the display scale, again whenever drawn larger (capped at 4096 pixels per side); mipmaps cover smaller uses. Images with currentColor are drawn tinted by the node’s color.

GPU lifetime

The shader, atlas and textures belong to the context and are released in rd_ctx_destroy only if the window still exists, which is why the user docs insist on destroying the context before CloseWindow.

Time: timers, animation, hooks

The clock

The context has one clock, ctx->now, set by rd_ctx_set_time (from GetTime() in rd_update, by hand in tests). Nothing reads the system time. Everything time-based in the library is therefore deterministic under test: set the time, lay out, assert.

Timers

timer.c keeps an array of timers with generational handles. rd_ctx_set_time runs due timers in due order. Two rules keep callbacks safe:

  • A timer set during a run gets that run’s epoch and doesn’t fire until the next clock update, so a callback that sets a zero-delay timer can’t loop forever within a frame.
  • A timer cleared from its own callback is marked and finished after the callback returns, so its data stays valid.

A repeating timer that falls behind fires once and skips ahead rather than bursting.

Event waiting

raylib’s EnableEventWaiting blocks in glfwWaitEvents without a timeout, so nothing can wake it at a time. rd_set_event_waiting hands the switch to raydom: rd_update disables waiting while a timer is pending or anything animates, and re-enables it when neither is true. Idle UIs cost nothing; a repeating timer keeps frames running.

Transitions

Animation state is per node (rd__anim, allocated only while something animates), listed in ctx->animating.

Starting. rd__transition runs inside style computation, right after build produces the new target style. For each animatable property (kinds VAL, COLOR, EDGES, CORNERS, SHADOW):

  • already animating toward the same target: keep showing the current value;
  • target differs from what’s shown, the property’s group is in transition_properties, and the duration is positive: record from (what’s shown), to, start, duration and easing, and show the start value;
  • otherwise: stop any animation and show the target.

Lengths animate only between equal units. height between auto and px is special-cased: from auto starts at the laid-out height; to auto re-measures the natural height every frame and ends as auto.

Ticking. rd__anim_tick runs first in rd_ctx_layout. It writes interpolated values straight into the computed styles, marks layout dirty for layout properties and restyles children for inherited ones, and frees state when nothing is left.

Because animated values live in the computed style, layout, hit-testing, anchoring and drawing need no knowledge of animation, which is how layout properties animate “for free” (at the cost of a relayout per frame for the moving part of the tree).

Explicit animations. rd_node_animate records a pending request (duration, easing, which properties, optional start values, the call time) and merges to into the inline style. The next computation consumes the request as transitions with those parameters, starting at the call time. done is an ordinary timer.

Easing is CSS’s cubic-bezier, solved with Newton’s method and a bisection fallback.

Layout hooks

See Layout. They’re here in spirit: they let code react to this frame’s geometry within the frame, the way a virtualized list must.

The C++ layer

include/raydom/raydom.hh is header-only and adds no state: every wrapper holds the context pointer and a handle.

TypeOwns
rd::ContextThe context (RAII, move-only)
rd::NodeNothing: {rd_ctx*, rd_node}; setters are const
rd::ClassNothing: {rd_ctx*, rd_class}; setters are const
rd::StyleAn rd_style value, with a setter per property
rd::EventA view of an rd_event*, valid during the listener

Handles are const

rd::Node and rd::Class setters are const and return const Node& / const Class& for chaining. They change the node or class in the context, not the handle, like std::span’s element access. This lets a lambda that captures a node by value call setters without mutable or a copy. New methods on handle types follow suit.

Callables

Lambdas go through one pattern: allocate the decayed callable with new (std::nothrow), pass a captureless trampoline as the C callback and the allocation as data, and pass a deleter as the destroy callback. If registration fails, the wrapper deletes the allocation itself. The C side owns the callable from then on, so captures live exactly as long as the listener, timer or measure function.

Setters from the X-macro

rd::Style gets its setters by expanding RD_STYLE_PROPS, with extra overloads per kind (edges from one, two or four values; corners from one; tracks from an rd_val; shadows from numbers). A new property gets its C++ setter without touching raydom.hh.

No exceptions

The layer compiles with -fno-exceptions. Allocation failures return null handles or false, as in C. Keep it that way: applications on platforms without exceptions are a target.

Extras

raydom::extras is a second library built only on the public core API. That constraint is the point: if a component needs something the core doesn’t offer publicly, the core gains a public feature that applications can use too. Per-context storage (rd_ctx_set_extension), post-layout callbacks (rd_ctx_on_layout), firing events (rd_node_dispatch), shared states, the checked state, focus scopes and roles all arrived this way.

Patterns every component follows

A component is a node. Creating one returns its root node, which the application appends anywhere. Internal parts are child nodes with classes from the theme.

State lives outside the node. A component’s state struct is the data of one of its listeners, with a destroy callback that frees it, so it’s freed exactly when the node is destroyed. Getters find the state through a registry keyed by node handle (rdx__lookup); the registry checks the node is alive before returning a pointer, which is the only proof the state hasn’t been freed. Controls use an index by slot number for O(1) lookup; the rest use the generic registry. Never use node userdata: it belongs to the application (see Conventions).

Changes are events. The component fires RD_EVENT_CHANGE (and INPUT for continuous controls) on its root with rd_node_dispatch, when the user changes it. Setters fire nothing, so an application syncing a component from its model can’t cause a feedback loop.

Looks are classes. rdx_theme(ctx) returns rdx_classes, one class per part. Parts call rdx__part, which adds the class and rd_node_set_share_states, so a part’s variants follow the component’s states: the box of a checkbox looks hovered while the pointer is anywhere on its row. State variants on parts are the main restyling surface; components set inline styles only for per-instance geometry (a slider’s fill width, a tree row’s indent).

Keyboard behavior matches the platform’s native control: roving focus in radio groups and tab bars, arrows, Home/End and Page keys in lists and sliders, Escape closing popups.

The popup manager

popups.c keeps one manager per context with the open popups (bottom to top), and registers four listeners on the root, once, in the capture phase:

  • POINTER_DOWN: close popups from the top until reaching one containing the target (or whose anchor contains it), or a modal.
  • WHEEL: close menus and lists the wheel isn’t inside.
  • KEY_DOWN: Escape closes the topmost popup and stops the event.
  • POINTER_MOVE: close tooltips whose owner was destroyed.

Closing returns focus to the popup’s opener if focus was inside it, and for modals restores the previous focus scope and calls on_close. Capture-phase listeners on the root run before anything else sees the input, which is how outside presses close a menu before the press reaches what’s under it.

Virtualized lists

A list is a scroll container holding a spacer as tall as all rows and a pool of absolutely positioned row nodes. Each list has a node-scoped layout hook (rd_node_on_layout), removed with the list and skipped while it’s detached: compute the visible range from this layout’s scroll offset and size (plus three rows of overscan each side), release pooled rows outside it (display: none), and bind rows for indices without one: empty the row, position it, call the application’s fill callback. Bound rows that stay in range are left alone, so scrolling costs only the rows entering view. Tables and trees are lists with their own fill callbacks.

Fixed row height is what makes this O(visible): any row’s position is index * height.

Toasts

Each position has a stack node in the overlay. Toasts slide in with rd_node_animate from an offset margin, and close by animating opacity, height and padding to zero (height from auto, so the stack closes up smoothly), then destroying themselves with a timer. A per-context list of live toasts lets rdx_toast_close find a toast’s state.

Design decisions and tradeoffs

Each entry: what was decided, why, what it costs, and what would make it worth revisiting.

Retained mode, not immediate mode

raylib has raygui, an immediate-mode toolkit. raydom keeps a tree because layout (flexbox, grid, text wrapping) needs the whole tree to size anything, animation needs state across frames, and accessibility needs a structure to describe. Cost: applications manage node lifetimes and mirror their state into the tree. Revisit: never; it is the premise.

A C core with a C++ layer

C23 is callable from everything and keeps the library easy to embed; the C++ layer recovers ergonomics (RAII, lambdas, builders) without making C users pay. Cost: every feature is written twice at the API surface, and the C API is verbose. Revisit: if the C++ layer starts needing state the C API can’t express.

Generational handles instead of pointers

rd_node is a value with a generation. Stale handles are detectable, so a destroyed node is a no-op everywhere instead of a use-after-free, and handles can be stored and copied freely. Cost: a check on every call, and public structs hold handles instead of pointers. Revisit: no.

Parallel arrays by subsystem

Node data is split into slots, styles, layouts, events rather than one struct per node, so each pass touches dense memory and subsystems don’t share a struct definition. Cost: a node’s data is spread out, and arrays reallocate together, so no pointer into them survives node creation. Revisit: if profiling shows the split hurting a pass that reads several arrays per node.

Zero means unset, and one X-macro

Partial styles as C designated initializers, merging that copies only what’s set, and every per-property operation generated from one list. Cost: “value zero” needs a unit or flag (rd_px(0)), and adding a value kind touches several expansions. Revisit: no; it’s what makes the C API pleasant.

CSS semantics, with deliberate differences

Flexbox and grid follow the CSS specs closely, so knowledge and bug reports transfer. The defaults differ where CSS’s are web-specific: flex_direction column (most UI stacks vertically), flex_shrink 0 (items keep their size unless asked; CSS’s shrink-by-default is a frequent surprise), automatic minimum size 0. Cost: CSS users must learn the differences, documented in the user book. Revisit: if users trip on them more than they would on CSS’s.

Classes and state variants, no selectors

Styles come from defaults, inheritance, classes in order, state variants, and the inline style. No selectors, no specificity, no cascade across the tree. Selector matching is the expensive, surprising part of CSS; classes plus variants cover component styling, and share_states covers the one common descendant case (.row:hover .box). Cost: no structural selectors (:nth-child, .a .b); applications add classes instead. Revisit: if component authors keep reaching for descendant selectors beyond what share_states gives.

One recursive measure function with caches

Layout follows Yoga’s model: rd__layout_node(key, perform) answers “how big would you be?” and “lay yourself out”, with per-node caches. It’s simple to extend (grid, text and images plug in as measured leaves) and near-linear with caching. Cost: callers must resolve a node’s own size properties into the key, and cache keys must capture every input (see normalize_key). Revisit: if a layout mode can’t be expressed as measure-then-perform.

Lazy recomputation

Mutations set dirty flags; work happens once in rd_ctx_layout. Listeners can make many changes cheaply, and an unchanged frame costs almost nothing. Cost: geometry read between a mutation and the next layout is stale, and some internal paths (focus) must compute styles on demand.

A display list, rebuilt every frame

Drawing walks the tree into commands, then a renderer executes them. The split keeps raylib in one file, allows headless render tests, and leaves room for other backends. Rebuilding every frame avoids retained render state and its invalidation bugs. Cost: a full tree walk per frame even when nothing changed; paint_dirty is tracked but not yet used to skip it. Revisit: for very large trees, by skipping unchanged frames first.

An SDF shader for boxes

Rounded corners, borders and shadows come from one fragment shader computing distance to a rounded rectangle, not from tessellated meshes. Antialiasing is exact and per-corner radii and per-side borders are cheap. Cost: a batch flush per rounded box; square boxes avoid it. Revisit: if batch flushes dominate frame time.

stb_truetype, no shaping

Fonts and text use stb_truetype: small, static, no dependencies, which fits single-binary apps. Cost: no ligatures, contextual forms or bidirectional text; Arabic and Indic scripts render incorrectly. Revisit: when those scripts matter; HarfBuzz is the answer and would be the largest dependency by far, so likely as an option.

The overlay is a child of the root

Popups need to draw above everything and escape clipping. A second root would have meant special cases in every ancestor walk (event paths, focus, selection order, “is this displayed”). As the root’s forced-last child with fixed geometry, the overlay needs none. Cost: it appears among the root’s children, and the “always last” rule lives in rd_node_insert_before.

Overlay scrollbars

Scrollbars draw over the content edge and take no layout space, like macOS. Showing or hiding a bar never reflows content, and layout didn’t change. Cost: a bar can cover content; layouts add padding where it matters. Revisit: if classic gutter bars become a requirement, as an option.

Animation lives in the computed style

Transitions write interpolated values into the computed style, which everything else already reads. Layout properties animate with no layout-side code, and hit-testing and anchoring follow. Cost: animating layout properties relayouts the moving part of the tree every frame. Revisit: if a common animation is too expensive; paint-only fast paths could skip layout for paint properties (they already don’t mark layout dirty).

An application-supplied clock

The context never reads the system clock; rd_ctx_set_time drives timers, animations and wheel gesture ends. Tests are deterministic, and applications control time (pausing, replaying). Cost: forgetting to set time stops everything; rd_update does it for raylib apps.

Extras use only public API

Components are built like an application would build them. This keeps the core honest: every capability a component needed became public. Cost: some features are slightly more general than one component needed.

Component state outside userdata

Userdata is the application’s. Components keep state in listener data plus a registry. Cost: a lookup per getter. The alternative broke the showcase, which reads userdata on hovered nodes as its own type.

Fixed-height virtualization

Lists and tables require one row height so any row’s position is arithmetic and work is O(visible). Cost: no variable-height rows. Revisit: with an estimated-height scheme that measures rows as they appear.

Blocking native file dialogs

rdx_dialog_* block until the dialog closes. Native dialogs are modal anyway, macOS requires them on the main thread, and blocking keeps the API one call. Cost: the window doesn’t redraw while a dialog is open.

Vendored code stays unmodified

stb, nanosvg and nativefiledialog are copied verbatim, with static linkage or #define renames to avoid symbol clashes. Updating is copying; fixes go upstream (the nanosvg fractional-gradient bug, for example). Cost: known upstream bugs stay until fixed there.

Byte offsets in public APIs

Selections, highlights and carets use byte offsets into UTF-8, because applications index their strings in bytes. Codepoints are internal. Cost: callers must not split a multi-byte character; the core clamps to character boundaries where it can.

Documentation samples are tests, and docs are per tag

Every sample in the user book is compiled, and most run, in the test suite, and each release tag publishes its own copy of the book. Docs can’t silently drift from the code, and old versions stay accurate. Cost: writing a sample means writing a small test program.

Debt

  • paint_dirty is written but never read. It’s the hook for skipping display list rebuilds on unchanged frames.
  • Track lists are never freed. They’re interned by content, so recreating the same lists is free, but code that creates ever-new distinct lists (track sizes computed from a live value) grows the pool until the context is destroyed. Auto-repeated tracks cover the common case (columns that follow the width); freeing would need styles to hold counted references.
  • Class changes scan every node. invalidate_class is O(nodes). Fine at startup; a per-class node list would fix it if classes start changing at runtime.
  • Linear registries. rdx__lookup and the popup and toast lists are linear scans. Fine for the numbers of components a UI has; controls already use an O(1) index.
  • Glyph atlas resets when full. A UI showing many sizes of many glyphs at once could thrash it. Multiple atlas pages would fix it.
  • No CI for tests. Only docs publishing runs in GitHub Actions.
  • rd_ctx padding. clang-tidy’s opt-in padding check flags 33 bytes; reorder fields when convenient.
  • nanosvg gradients with unitless fractional coordinates render as a flat color (upstream bug; use percentages).

Adding a style property

Example: a letter_spacing length, inherited, affecting layout.

  1. Declare it. Add a line to RD_STYLE_PROPS in include/raydom/style.h:

    X(letter_spacing, rd_val, VAL, 1, 1)  \

    Pick the kind (VAL, COLOR, EDGES, CORNERS, SHADOW, ENUM, …), whether it’s inherited, and whether it affects layout. Position in the list is the struct layout; append near related properties.

  2. Default it. Add it to default_style in src/style.c. A debug build asserts at context creation that every property has a default.

  3. Use it. Read ctx->styles[i].computed.letter_spacing where it matters (here, text.c tokenizing and the renderer’s glyph placement). Changes already mark layout dirty because of the affects_layout flag.

  4. Animate it, if it should. For kinds VAL, COLOR, EDGES, CORNERS, SHADOW, add it to GROUP[] in src/anim.c under the right RD_TRANSITION_* group. Without a group it changes at once.

  5. Document it. Add a one-line description to DESCRIPTIONS and the name to a section of GROUPS in docs/tools/preprocess.py. The docs build fails until you do.

  6. Test it. Cover inheritance and the default in tests/test_style.c, and the behavior in the subsystem’s test.

The C++ setter (rd::Style::letter_spacing) and the property reference page generate themselves.

A property with a new enum type also needs the typedef enum ... : uint8_t with _UNSET = 0 first. A new kind of value needs a MERGE_, EQ_, SET_ and RD_HH_SETTER_ case, a kind in anim.c, and a default formatter in preprocess.py.

Adding an event type

  1. Add the type to rd_event_type in include/raydom/events.h, before RD_EVENT_TYPE_COUNT, with a comment saying where it’s fired and whether it bubbles. Appending keeps existing values stable.
  2. Add any fields it needs to rd_event, and accessors to rd::Event in raydom.hh.
  3. Fire it with fire(ctx, type, target, button, bubbles) from the subsystem that owns the moment, or with rd_node_dispatch if it’s a component-level event. If it has a default action, run it after dispatch and only when fire reports it wasn’t prevented.
  4. Document it in the event table of the user book’s Events chapter.
  5. Test the target, the propagation and the default action in tests/test_events.c.

Most component-level needs are covered by CHANGE and INPUT with rd_node_dispatch; prefer those over a new type.

Adding an extras component

Follow the patterns in Extras. A checklist:

  1. API in a header under extras/include/raydom/extras/: rdx_<thing>_create returning the root node, getters and setters, and a desc struct if there are options. Setters fire nothing.
  2. State in a struct owned by one listener’s data, freed by that listener’s destroy callback. Register it with rdx__track so getters can find it; never use userdata.
  3. Classes in rdx_classes (theme.h) with defaults in theme.c. Parts use rdx__part to share states. Interactive parts get quick() for color transitions.
  4. Role on the root (add one to role.h if AccessKit has it and raydom doesn’t), and focusability through the role or focusable.
  5. Keyboard behavior matching the native control.
  6. Events: RD_EVENT_CHANGE on the root via rd_node_dispatch when the user changes it; INPUT for continuous changes.
  7. Popups register with the manager in popups.c so dismissal, Escape and focus return work.
  8. C++ wrapper in the matching .hh, owning callables with new (std::nothrow).
  9. Tests in tests/, driving it through rd_ctx_pointer, rd_ctx_key and rd_ctx_set_time. Include a check that its internal nodes leave userdata null.
  10. Docs: a section in the extras chapters with a docs/examples/ program, the theme classes in its restyling table, and the header in the installation page’s table.
  11. Showcase: a demo in the tour.

If it needs something the core can’t do through public API, add the public core feature first, documented and tested on its own.

Writing tests

Shape

Each subsystem has a test program in tests/ (test_layout.c, test_popups.c, …), listed in the foreach in the top-level CMakeLists.txt. A test is a main calling functions that use CHECK(cond) from tests/check.h, which prints the failing expression and line and counts failures; TEST_RESULT() returns non-zero if any failed. C++ tests (*_cpp.cc) exercise the C++ layer.

Tests link the core and extras and can include private headers from src/ to check internals (rd__display_list, rd__scrollbar, ctx->sb_hot). Prefer public API; reach inside only to check something the API doesn’t expose.

Headless by default

Nothing but render.c touches raylib, so tests don’t open windows:

  • Fonts: rd_font_load_file(ctx, RAYDOM_TEST_FONT), a font from raylib’s examples.
  • Layout: rd_ctx_layout(ctx, w, h), then rd_node_rect and rd_node_bounds.
  • Input: rd_ctx_pointer, rd_ctx_key, rd_ctx_text; layout first so hit-testing has geometry.
  • Time: rd_ctx_set_time(ctx, t) then rd_ctx_layout to advance timers and animations deterministically.
  • Drawing: rd__display_list and check commands (tests/test_render.c, tests/test_image.c).
  • Pixels: rasterize SVG with rd__image_rasterize and read pixels.

What to cover

  • The behavior and its edges (empty, one, many; clamped values; stale handles).
  • Every default action and that prevent_default stops it.
  • Destruction during dispatch, for anything with listeners.
  • For components: keyboard paths, setters firing nothing, userdata left alone.

Floats

Compare with a tolerance (near(a, b), usually 0.01, or 0.6 for laid-out pixels after animation).

Documentation examples

Programs in docs/examples/ are tests too (doc_<name>_<ext>). They assert what the book claims; keep them passing when changing behavior, and update the prose with them.

Sanitizers

Run the suite under just test, which builds with ASan and UBSan. A test passing without sanitizers but failing with them is a bug, not flakiness.
